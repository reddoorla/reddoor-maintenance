## 2. The instrument, and how it lied to me twice

This repo's top rule is _prove the instrument before you trust its verdict_. The
obvious instrument for "was this plan executed?" is the checkbox state inside
the plan file. **That instrument is dead.** Measured across all 84 plans:

```
plans=84  ticked_boxes=81  unticked_boxes=3572  total=3653
plans with >=1 tick: 9   plans with boxes but zero ticks: 70
plans naming a Spec:  21
```

2.2% of checkboxes are ticked. `2026-07-01-forms-spam-defense.md` carries 108
unticked boxes and describes a system that has been live since #348. Plans are
ticked in the executing agent's context and the ticks are never written back.
**A plan file cannot tell you whether it ran.** Anything a meta-week does with
these files has to start from that.

The second instrument I built — "do the source paths this plan names exist?" —
**failed on its first run and I nearly reported the failure as a finding.** It
scored seven plans at 0%:

```
2026-07-05-blux-pipeline-plan1-slices.md    0/21
2026-07-06-health-gate-plan1-starter.md      0/6
2026-07-13-blux-render-starter-promotion.md  0/9
2026-08-31-starter-track-split.md            1/28
2026-09-09-report-edits-b-edit-mode.md       0/10
...
```

All of those resolve against the wrong repo. Re-run across all 41 checkouts:

```
2026-07-05-blux-pipeline-plan1-slices.md   21/21 100%  the-pointe
2026-08-31-starter-track-split.md          22/28  78%  reddoor-starter-blux

2026-09-09-report-edits-b-edit-mode.md      3/10  30%  reddoor-website   ← still low
```

Only after that correction is a low score evidence. A third false alarm: I
grepped `src/` for `autoreply|auto_reply|auto-reply` to test whether the
2026-09-03 auto-replies plan had run, got nothing, and was about to call it
unexecuted. The code calls the feature `_reply` / `reply-copy.ts`, and it
shipped the same day the plan was written (`0005dc15`, #681). **Three
instruments, three false FAILs, zero true ones on first run.**

The instrument that actually works is the git log, cross-referenced per feature.
That is what section 3 is built on.
