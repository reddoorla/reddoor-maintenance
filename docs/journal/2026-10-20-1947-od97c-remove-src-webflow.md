## 2026-10-20 — Operator decisions 97(c): `src/webflow` and `reddoor-maint webflow` removed (this PR)

The operator's answer to 97(c) was to keep `src/blux`, remove `src/webflow`, and archive canvas-starter himself. This PR is the middle part. `src/webflow` had one commit (#466, 2026-07-28) and no reader outside its own CLI command, and the 10-19 conversions did not use it (the decision file's words), so the import pipeline was 1,029 lines of source (the meta-week census) that only its own tests ran. The diff is 27 files deleted and 3,275 lines gone. `reddoor-maint webflow capture x` now reaches the CLI's `command:*` handler and prints `error: unknown command 'webflow'` with exit 1. A new source-spawned test pins that, because the string is printed in only one place, after `bin.ts` has loaded and cac has matched nothing.

The brief expected the verify-first grep to find two files outside `src/webflow`, and it found three. The third is `src/prospect/stack.ts`, whose Webflow entries are CMS-detection regexes (`/webflow/i`, `website-files.com`), not imports, so the stop condition (something imports it) did not fire. The one cross-module edge ran from `webflow/to-plan.ts` into `blux/emit/plan.ts`, so blux loses a caller and nothing else.

The mutations both went red. Leaving the `bin.ts` registration with the command file gone breaks `pnpm build` (esbuild: `Could not resolve "./commands/webflow.js"`), `pnpm test:dist`, `pnpm typecheck` (TS2307), and the whole `pnpm test`, which dies in vitest's global setup because it rebuilds a stale `dist/`. I had not known the suite rebuilds `dist` before it runs. Deleting `src/blux/emit/plan.ts` gives 57 type errors across 22 blux files, and 25 of 75 blux test files fail to load, so blux guards that file itself and webflow's tests were not hiding a blux dependency.

One full-suite failure is not this PR's: `tests/scripts/dropbox.test.ts` "re-executes through HTTPS_PROXY" fails the same way on untouched `main` in a cloud container, because an undici proxy warning lands on stderr ahead of the expected line. The tests lens measured coverage with it excluded: 91.36% statements, 86.55% branches, 90.19% functions, 92.44% lines, against floors of 78, 67, 76 and 80.

The review was one round with three lenses (wiring, tests as instruments, changeset and scope), and it was minors only. Folded in: the changeset now says "Breaking for the CLI", as 0.97.0's and 0.100.0's removals did (both minor, and the CHANGELOG has no major section at all), and the test's exit-code fallback is `-1`, so a signal kill can no longer satisfy `toBe(1)`. One issue is filed for the forward pointers that `docs/webflow-conversions-2026-10.md` and `docs/superpowers/specs/2026-10-19-cleanup-worklist.md` could take. Both are dated plans, so this PR leaves them alone. The tests lens planted a throw at the top of `bin.ts` as a negative control, and the wiring lens, which was reading the same worktree, saw it. Parallel lenses on one worktree can see each other's mutations.
