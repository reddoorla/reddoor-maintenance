## 2026-10-26 — The cockpit on SvelteKit 3 and adapter-netlify 7 (P1-69)

Landed in reddoorla/reddoor-maintenance#1740. It supersedes Renovate's #1704 (GHSA-27mw-82g8-phjj, CVSS 0.0, fixed only in kit 3) and Dependabot's #1720.

**Why it was red.** Kit 3 refuses to start beside a `svelte.config.js` (`config_file_unsupported`) and takes its options through the `sveltekit(...)` plugin. The cockpit's options moved unchanged into `vite.cockpit.config.ts`. Kit 3 also needs adapter-netlify 7, so the two moved together, as on the eight sites in P1-53.

**What kit 3 and adapter 7 changed underneath, each measured on a build:**

- **`svelte-kit sync` finds the config only through `--config`.** The cockpit's Vite config is not named `vite.config.ts`. A bare sync exits 0, writes `./.svelte-kit/types/src/routes` for an app that does not exist, and rewrites `node_modules/$app/tsconfig.json` to point at it. Nothing errors, and svelte-check then reads the wrong types. Every sync now goes through `pnpm cockpit:sync`, and `tests/cockpit/kit-config.test.ts` fails on any bare one in a package script or workflow. `time-travel.yml` had one.
- **The generated tsconfig moved** from `cockpit/.svelte-kit/tsconfig.json` to `node_modules/$app/tsconfig.json`, so `cockpit/tsconfig.json` extends `$app/tsconfig`. This is the `tsconfig_extends_missing` error from #1704's log.
- **Adapter 7 writes Netlify's Frameworks API** (`.netlify/v1/`), where adapter 6 wrote `.netlify/functions-internal`. It also takes `publish` as its own option, defaulting to `build/`, and no longer reads it from netlify.toml. Left at the default, the build is green and Netlify publishes `cockpit/build`, which holds no assets. The option now names it.
- **Output against kit 2 on `main`:** the same 22 manifest routes; one `/*` function with the same `excludedPath` and `preferStatic`; the same published files except `_headers`. The immutable cache header moved into `.netlify/v1/config.json` with the same value.
- **On the deploy preview:** pages, sign-in, `__data.json`, a dashboard API route, `_app/version.json` and the three standalone functions (form ingest, prospect report, audit-report JSON) answered production's status, redirect target and `cache-control`. Netlify's own checks matched #1729 on kit 2: one header rule, no redirect rules.
- **Kit 3 stops sending the `Link: rel=preload` header** unless `output.linkHeaderPreload` is set. It is set. On `/fleet` the header now has kit 2's shape: the same CSS preload, and modulepreloads that differ only in chunk hashes.
- **Smaller API moves:** `Handle` now comes from `@sveltejs/kit/hooks` and `AfterNavigate` from `$app/navigation`. A data-request redirect now carries `status: 302`, and the server manifest's `routes` moved up from `_`.
- **Renovate had rewritten the published package's peer range** to `"^3.0.0 ^3.0.0"`. That would have told every kit-2 fleet site it was incompatible. The PR keeps `^2.0.0 || ^3.0.0`.

**The cockpit carries kit 3.1's Forward crash (#1722).** With storage blocked: open `/`, follow the link to `/fleet`, reload, Back, Forward. The URL is `/fleet`, the home page stays on screen, and the console shows `TypeError: Cannot set properties of undefined (setting 'scroll')`. Kit 2 shows Sites, and with storage working both are right. It is kit's bug, already the operator's call fleet-wide, so the cockpit was added to #1722 rather than patched here.

**Review.** Three lenses ran in round 1: deploy surface, test integrity and kit 3 runtime. The runtime lens drove 51 requests through both built servers and found parity, CSRF included: `trustedOrigins: ["*"]` still compiles the origin check out. The test-integrity lens found the one major. The publish-directory test passed on an earlier build's `cockpit/build`, because adapter 7 clears only its own publish directory, so dropping the option stayed green on any reused checkout. That test now requires the published `_app/version.json` to equal this build's. Its minors were folded in:

- the sync scan missed a double space, and missed `npx svelte-kit sync && vite build --config …`, where the flag belonged to the other command;
- the "control" resolved with `configFile: false` and so could not fail;
- the build staleness check ignored the lockfile.

Round 2 was a single reviewer over the whole PR. It ran four mutations, and the version check went red on a misnamed publish directory. It found only minors, so the round is clean.

- **Folded in:** the sync scan accepted `-c=vite.cockpit.config.ts`, which kit reads as the file `=vite.cockpit.config.ts`. It flagged `./`-prefixed and quoted paths. It missed `svelte-kit@3 sync`, an option before `sync`, and a line continuation. All fourteen cases now classify right.
- **Filed:** a deleted source file leaves a stale local build (#1744, predates this PR), and adapter 7's latent `read()` path (#1745).

**Belief corrected.** I wrote the publish test as proof that adapter 7 was configured, and on my own run it was: I had moved the stale directory aside before the mutation. A fresh CI checkout catches the mutation and a laptop does not. The test only proves the config when it compares against this build.
