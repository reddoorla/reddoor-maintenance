# 2026-11-23 — W1: three review rounds on the draft and withdraw states (#2257)

Follows `2026-11-23-2016-w1-approve-before-link.md`, which was written before review and stands as written.

Round 1 found that about 1 token in 64 starts with "-", which the CLI's argument parser read as a flag, so those reports could never have been approved or withdrawn. The command now takes `--token=<t>` and `--supersede-by=<t>`. Round 2 found that swapped supersede arguments took the newer, live report down with no way back through the command, and that approve accepted a partial run. Supersede now refuses a newer report that is not live, rows for different sites, swapped order, and an old row that was never approved (that one is withdrawn, not superseded, or its never-sent link would start pointing at the live report). Approve refuses a partial run unless `--partial` is given. Every write checks its update count, so a withdraw that lands between the read and the write is reported rather than hidden.

Round 3 was clean: minors and nits only. Two were folded in because the PR already touched their files: the JSON route's 404 now carries `cache-control: private, no-store` like its 200 and 410, so a draft's 404 cannot outlive its approval in a cache; and a complete run's last line ("Draft, not approved… `--token=<t> --approve`") now has a test, where before only the partial run's "DO NOT SEND" did. Returning null from `reviewLine` for a complete run turns it red. Three were filed: #2263 (a bearer without the edit-session header stamps `opened_at`), #2264 (the cockpit does not mark an approved partial run), #2265 (equal `created_at` defeats the supersede order check). #2259 (print the PDF on approve) was filed in round 2.
