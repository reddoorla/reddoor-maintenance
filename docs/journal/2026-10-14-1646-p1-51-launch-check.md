## 2026-10-14 — `launch` refuses a site missing a launch step, and the list it checks is written down (P1-51, #1377, `917e8bb`)

Both Williamson sites went live on 10-13 with no Analytics, no Search Console, no contact and no schedule. `launch` checked none of those, and each one fails late and quietly. GA does not backfill. A report with no property drafts a blank analytics section. A go-live email with no recipient drafts fine and can never be approved. `docs/runbooks/site-launch.md` is now the one ordered list, 19 steps, from DNS to the first report with analytics. `reddoor-maint launch-check <site>` checks eight of them and prints `ok`, `missing` or `unverified` for each. `launch` runs it as step 0b, before the first GitHub write, and stops unless every step is `ok` or named in `--allow-missing`.

**Why `unverified` blocks like `missing`.** `missing` is a fact about the site. `unverified` is a fact about the run: no credentials, no browser, the API did not answer. A check that reads "could not tell" as a pass is the 2026-08-12 failure in this repo's first rule. So the only way past a step nobody could verify is to name it.

**The GA check needed an authority nobody was reading.** The row stores the numeric property ID and the site's code ships the `G-` measurement ID, and nothing joined the two. The analytics audit pairs checkout against row, which says what the site intends, not what feeds which property. The GA4 Admin API lists a property's web streams. `ga-tag` asks it which measurement IDs belong to the row's property, then requires a browser load of the live url to receive one of those loaders. Live negative control: MSOT's property written on Data Dynamiq's row reads `ga-tag missing ("loads G-V11LZYNMY2, not … G-BZ0WQMEE8L")`. Property `999999999` reads `ga-property missing (PERMISSION_DENIED)`. The Admin API answered for the session's subject on the first call. No scope change was needed beyond `analytics.readonly`.

**Every subject, no failover.** `ga-property` and `search-console` read as each `GA_SUBJECT` subject in turn. The failover list only helps if each subject has access, which the cutover runbook already said and nothing enforced. In this container `GA_SUBJECT` is `tucker@reddoorla.com` alone, so "answers for tucker@" is all these runs prove. They do not prove `reports@`, and the line names the subject so that difference stays visible.

**Proven.** On the final head, Data Dynamiq reads 8 of 8 `ok`. Both Williamsons read NOT READY on the rows as found, with 7 `missing` and `privacy unverified`, because their url was `http://` and so was not fetched. MSOT reads `privacy missing` alone. That one is real: its `/privacy` and `/privacy-policy` both 404, and it runs GA4 (#1376). The instrument found a fleet gap on its first known-good run, and the run was meant as the positive control.

**Review.** Five lenses over three rounds. Round 1's majors were all one shape: an answer read from the wrong place. `url` and `privacy` judged whatever host a redirect landed on, so a parked domain answering 200 was `ok`. The `/privacy` link regex accepted Google's own `/privacy`, which every reCAPTCHA notice carries. And the gate trusted its lines array to be complete, so `[]` meant ready. Round 2's major was the same shape once more. An apex row url that redirects to `www` passed `url`, and the Search Console check was then judged against a host that serves nothing. `url` now requires the host the site lands on. Round 3 was minors only (#1373–#1375). 31 named mutations each turn a test red. M18 (a throwing readiness becomes `[]`) survived once: the absent-step fill stopped it anyway, so the test was right about safety and silent about why. It now asserts the error message.

**Williamson, worker side.** The row urls were set to `https://www.…/` through the site mirror. Header images were stored with `header-image --write-back` and looked at: clean plates of each live home page. Both repos now carry a `/privacy` port of the starter, with the footer link and GA disclosed ahead of the tag (williamson-homes#39, williamson-construction-co#29, CI green, previews 200). The Admin API's account summaries show no Williamson property visible to the subject (16 properties), and Search Console shows none either (12 sites).
