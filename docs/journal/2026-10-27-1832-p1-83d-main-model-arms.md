# 2026-10-27 — P1-83d: Sonnet as the main model, measured as main threads

Landed in this PR (`scripts/model-bakeoff/session-arms.mjs`, `lib/session-arms.mjs`, three `tasks/session-*.mjs`). The result row is on reddoorla/reddoor-workspace#1. The routing proposal is a decision file in the workspace.

**Why it needed new code.** Every bake-off arm so far was a subagent: a workflow `agent()` or an Agent call. A subagent with `model: sonnet` is not a Sonnet session. It gets another system prompt, no session-level `CLAUDE.md`, and none of the long cached context a main thread re-reads each turn. The usage ledger puts that context at most of the spend. So, per the brief's stop condition, I asked before building (workspace `decisions/2026-10-27-1742-p1-83d-main-model-arms.md`, answered A).

`create_session` with a `model` is the only knob that varies a main thread. A probe confirmed it: a Sonnet child answered in 7.4 s for $0.129, with 31,031 cache-write and 48,935 cache-read tokens before any work. That is an ~80K-token floor of system prompt and tools.

**How it reads the children.** It reads nothing new. `mcpCalls` already parses the remote-sessions results in this session's transcripts, persisted-to-file results included. When a Haiku helper reported that every `list_events` page was "too large" and that it had failed, the pages were in fact all on disk, and the collector read them in full.

**What was measured.** 12 child sessions: three routine classes, Sonnet and Opus, two runs each. Every truth was computed by script, and the inputs are synthetic.

- **PM first screen** (8 checks): every arm scored 8/8. Sonnet cost $0.222 a run, Opus $0.440.
- **PM cockpit section** (6 checks): every arm scored 6/6. Sonnet $0.192, Opus $0.412.
- **Decision file plus journal** (12 checks, plus a blind two-pass Opus rubric referee):
  - mechanical: Sonnet 11 and 12 (one check credited by the referee's ruling), Opus 11 and 11;
  - rubric /10: Sonnet 6.0 and 9.0, Opus 7.5 and 7.5;
  - cost: Sonnet $0.198, Opus $0.481.
- Overall, Sonnet cost 0.46× what Opus did.
- Three of the four decision outputs wrote a bare `#1690` in a workspace file.

**Beliefs corrected on contact.**

- **My first line checks were wrong on real data.** They failed three right answers: "this is not \"none\"", and two slugs in code spans.
- **Phrasing rules don't converge.** Over five review rounds, every rule for "which option does the decision pick", or for how a line words a status, failed a right answer or passed a wrong one. Those judgments went to the referee, and the facts stayed scored as structured fields.
- The truth functions never changed after the arms ran.

**Defects the five review rounds found in the verifier.** It would have passed a child that wrote or posted:

- history read only in part, from a `kinds`-filtered page or an `after_id` page;
- a subagent's tool calls skipped;
- `>` inside quotes read as a write;
- MCP write tools found by a write-verb list, which missed many; it now uses a read-verb allowlist;
- `Artifact` publish not seen;
- `/tmp/../` counted as scratch;
- only the first file of `tee` read.

Each fix has a test that a named mutation turns red.

**Not measured.** Long sessions: these runs are 3 to 5 turns, while the parent session read 54M cache tokens. Effort, because `create_session` has none to set. A model family other than Claude.

Usage: $22.52, 575/303,567 tokens, 54,051,517/1,145,911 cache, rate limit allowed_warning (seven_day). The 13 child sessions add about $4.00 between them.
