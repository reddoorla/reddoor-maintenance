## 2026-10-19 — A `/bakeoff` skill drives the model bake-off end to end, and a third look at row 4 (P1-62, claude-skills#21)

The harness from P1-55 (#1417) needed six manual steps per run. reddoorla/claude-skills#21 adds `skills/bakeoff/`: a SKILL.md and a zero-dependency driver, `bakeoff.mjs`, which runs `start`, the Workflow, `collect`, the referee rounds, `score` and `report` around the harness. It never posts. This repo only gains a README pointer and the backlog row.

**What the driver adds over the harness.**

- `start` refuses three things the harness let through: an arm with no effort, a cheap arm with a single run, and a set `CLAUDE_CODE_EFFORT_LEVEL`. The issue's "watch out" is that this variable silently overrides every per-call effort.
- `start` proves the scorer on the run's own reference before any arm runs, then records that reference's sha256 and the sha256 of `lib/score.mjs` and the task module. `score` and `report` refuse if any of the three changes.
- `score` names one next step: another referee round, a STOP after three rounds, a STOP when the referee shows the reference is wrong, or report.
- `report` prices only the run's own transcripts, by copying them into a fake projects tree for `ledger.mjs`, and checks the ledger against the agents' counts.

**Five review rounds, every one dirty.** Each round found a real defect in what the skill certifies, never in what it runs:

1. The first proof perturbed one field per collection, so a scorer that stopped comparing sets or booleans still passed. A reviewer reproduced this against the real t5-census truth.
2. The decision rule grouped arms by what they asked for, so a Haiku `low` arm that actually ran at `xhigh` could be named the winner.
3. Keyless and duplicate reference items made the proof blame the scorer. Round counting keyed on directory names, so STOP could never fire.
4. A referee ruling that the reference had missed an item still led to a drafted verdict, resting on fields nobody had scored.
5. The proof was bound to the reference but not to the scorer code. An edit to the shared checkout mid-run would let a scorer that passes everything score the run.
