# 2026-10-27 — P1-83: a per-model usage ledger for all Claude Code work

Landed in reddoorla/reddoor-maintenance as #1825 (`scripts/model-bakeoff/usage-ledger.mjs`, `lib/usage.mjs`). The data live in the workspace's private `usage/`, and the figures are on reddoorla/reddoor-workspace#3, not here, because this repo is public.

**Why.** The operator wants to know which model does which work, across all his Claude Code work, before subscription pricing changes. Each cloud session's server `result` events carry a per-model `modelUsage` map, and they survive archiving. Nothing was collecting them, and nothing kept the per-agent split before its container died.

**Three probes changed what was built.**

- **(a) The server never sees a subagent's own messages.** A one-call Haiku control left only its prompt, a `task_started` event and the Agent tool result in the server events. So the main-thread versus subagent split can only come from the container's JSONL, and an end-of-session harvest is the only way to keep it.
- **(b) Neither the brief's `get_session` gap nor the newest result was the session total.** `modelUsage` is cumulative but restarts from zero when a CLI process does not restore it, so a session's bill is the sum of its runs. `get_session` is a floor: it loses a process's unreported tail. Both were believed to be "the" total that morning.
- **(c) `list_sessions` reaches back months, not days.** Remote Control sessions are listed with no usage at all, so laptop work is only measurable on the laptop.

**Six Opus review rounds; the design changed twice.**

- **Rounds 1 and 2:** each found real figures from this account in the public diff, first in the README, then borrowed into the fixtures. Each time the branch was restarted with clean history (`-v2`, then `-v3`); the deny list refuses force-pushes.
- **Rounds 2, 3 and 6:** each found that merging stored _rows_ loses or doubles money on some order of harvests. Rounds 2 and 3 found it in the server rows, round 6 in the transcript rows. Every patched merge rule failed on the next order. The fix that held was to store the raw records instead (`results.jsonl` by result uuid, `messages.jsonl` by `message.id`), merge them as a union, and rebuild every row on each write. Rounds 4 and 6 then permuted real harvests 24 to 120 ways and got byte-identical output.
- **Rounds 5 and 6:** each still found a major, so the PR went to the operator twice. He chose a sixth round, then landing.

**Corrected on contact.**

- **The Sonnet default was not in force.** The workspace's `CLAUDE.md` said `.claude/settings.json` makes unnamed subagents run on Sonnet. In this session the variable reached neither the CLI process nor the shell, and six harvest agents ran on Opus until the operator asked. They were stopped and relaunched naming `model: sonnet`; the correction is a decision file for the cockpit.
- **The test that fails locally is the container, not the code.** `t4-plan-task.test.ts`'s "stale install" case fails in this container and on an untouched `main` alike: its box sees pnpm 10.28. CI passes it.

**Mutations named in the brief**, each turning a test red:

2. dropping the last model in a map;
3. reading `model_usage_since_last_result` in place of the cumulative map;
4. putting a subagent message on the main thread;
5. splitting on U+2028.
