# 2026-11-23 — The checks the Technical report leans on now say what is true; `--technical` runs only the unpaid stages (W4)

Landed in: this PR (`claude/w4-technical-checks`). The website half, the Technical report itself, is reddoorla/reddoor-website's `claude/w4-technical-report`, held until W1 (approve before link) and W3 (read the pages that matter) land.

**Why.** The 11-23 audit-system review (workspace `audits/2026-11-23-audit-system-review/`) designed a Technical report for the buyer who says "it's slow, something is broken, is it secure": a re-cut of one run from deterministic fields only. Four checks it would lean on printed false or alarming things on stored rows (TEC-04, 05, 06, DES-13, DES-14, LGL-05), and a fresh run could not skip the paid stages.

**What changed.** DMARC has three states: `p=none` is "monitoring only", a fail with its own evidence; it had passed as "A DMARC record, so SPF is enforced" on three of the four stored domains with a record. `noindex` on a legal, thank-you, search or login path passes as deliberate. The crawl keeps thrown errors (`pageerror`, new `vitals.scriptErrors`) apart from `console.error` lines, and only thrown errors fail `console-errors`; a run stored before the split reads as unmeasured rather than guessed. An address with `{{` is a template defect under `template-leakage`, not a page missing from the sitemap. HubSpot's tracking and banner hosts are "HubSpot tracking" under analytics; HubSpot CMS comes only from the hosts that serve HubSpot pages or the generator meta. The crawl's browser context asks for reduced motion. axe leaves the documents of cross-origin frames out. Header reasons are an observation and its ordinary consequence, `frame-ancestors` satisfies the X-Frame-Options check, and the version-leak evidence names the product, never the build. `prospect-audit --technical` skips analyze and probes (and so accuracy).

**Beliefs corrected on contact.** The first frame exclusion, `exclude([frame, "html"])`, is silently ignored by axe 4.14: the new browser test's "no button-name inside a cross-origin frame" failed on its first run, so the instrument was the suspect. A probe of five forms showed `[frame, "body"]` and `[frame, "*"]` exclude the frame's document while keeping `frame-title` on the site's own `<iframe>`; excluding the frame selector alone drops that too. The code uses `"*"`, and a test pins `frame-title` surviving.

**Measured.** Mutations, each run and reverted: `p=none` read as enforcing turned 2 DMARC tests red; removing `reducedMotion` made the fade-in fixture report contrast nodes (1 red); pushing styled `console.error` into `scriptErrors` turned the zero-script-errors test red. Every "absent" browser assertion has a control beside it that reports the thing when it is really there (pale text, a throwing script, the same widget in a same-origin frame). Full suite: 14,665 passed, 1 failed, and that one (`tests/scripts/dropbox.test.ts`, the HTTPS_PROXY re-exec) fails identically on untouched `main` in this container.

**Test changes.** `site-checks.test.ts` "catches a JavaScript error" now supplies the error as `scriptErrors`: the brief's Done-when changes what `consoleErrors` alone means. The CLI registration test lists `--technical`, as it exists to demand.
