## 2026-11-23 — A finished prospect audit is a draft until a person approves it; a wrong one can be withdrawn (W1, branch `claude/w1-approve-before-link`)

Why: the 11-23 audit-system review found that a finished run became a public link the moment it was saved, that nobody had to read it first, and that a report known to be false could not be taken down, only edited by hand in the table, which erased what it had said. Its fix list was a draft state with approval on record, a withdraw that 404s, and a pointer from an old report to its replacement. The website half is reddoorla/reddoor-website#379.

`prospect_audits` gains `approved_at`, `approved_by`, `withdrawn_at`, `withdrawn_by` and `superseded_by`, one column per migration (0059 to 0063) for the reason 0015 gives. NULL `approved_at` is a draft. The JSON route serves a draft only to a request presenting `PROSPECT_EDIT_TOKEN` as its bearer. The `x-reddoor-edit-session` header was not enough, because it is trivially spoofable and its comment says so. A withdrawn row 404s to everyone, the editor included. A superseded row answers 410 with the newer token, but only while the newer one is live: pointing an old link into a draft would defeat the draft. The chain is followed for at most five hops. `prospect-audit-review --token=<token> --approve | --withdraw | --supersede-by=<token> --by <name>` is the only writer. The token is a flag written with `=`, because about one token in 64 starts with "-", which cac reads as an option (review round 1); approving a partial run needs `--partial`. Approve refuses a withdrawn row, so bringing a report back is a deliberate hand edit and never a mistyped token. Supersede refuses two rows of different `site_key`s, so a typo cannot send a prospect to someone else's audit; it also refuses a newer report that is not live, an "older" one that is in fact newer (swapped arguments took the live report down, review round 2), and an old row that was never approved, which is withdrawn instead. Nothing ever rewrites `result_json`.

The bearer check moved out of the overrides route into `src/prospect/edit-token.ts`, which that route's own comment asked for the day a further route needed it. Override entries now accept `hidden: true`, validated as a known key: a non-boolean is `invalid`, `false` is not stored.

The CLI's last line is now the review verdict, because it is the line an operator acts on: "Draft, not approved", or "DO NOT SEND" for a partial run. The internal email says the same. One behaviour went: the save-time PDF. The print route 404s a draft to the renderer, so the PDF is no longer attempted, and the email says why. Printing one after approval is not built. The cockpit's /audits list now shows each report's state; its parity snapshot gained only those lines.

Mutations, each turning a named test red: removing the draft check (3 tests, including "a draft token returns 404 without the edit session"); serving withdrawn rows ("a withdrawn token returns 404, to the editor as well").

Belief corrected: the migration is not neutral. A new NULL column, read as "draft", turns every link sent before today into a 404 on the first `openDb` after deploy. That is a table write in effect, so this PR is held on the operator's answer to the workspace decision `2026-11-23-2011-w1-existing-prospect-audit-rows`, and must not land before the website half is on `main`.
