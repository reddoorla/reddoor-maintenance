## 2026-10-26 (overnight, about 8:50pm–10:15pm PT) — #1501's score-time half: t4's gates run in a Linux box, after four review rounds

Landed in this PR, #1802. Decisions: `decisions/2026-10-27-0305-p1-55-bakeoff-sandbox-1501.md` and `decisions/2026-10-27-0352-p1-55-1501-sandbox-platforms.md` in the workspace (guard now, then the score-time box, on Linux only).

**Why.** t4's gates execute the agent's code: `pnpm check`, lint, the suite, its own tests, and the held-out run. #1795 made a write task say `--unsandboxed` out loud. This PR closes what runs at score time:

- no network;
- the root clone, every agent's repo, the other arms, the other tree and the run's answer files all read as empty;
- only the gate's own tree, report dir and TMPDIR are writable.

The agents' own sessions are still unboxed. That half needs arms launched as headless sessions inside a namespace, which is the operator's call (option (c) of the first decision).

**The first design was a mount namespace, and review round 1 broke out of it in one line.** `unshare --mount --map-root-user` makes the gate root inside its own user namespace. That root holds `CAP_SYS_ADMIN` over the namespace's mounts, so:

- `umount` of a hiding tmpfs worked;
- so did a `remount,rw` of `/`.

The reviewer also found `/dev` and `/dev/shm` writable, and earlier runs beside this one visible. My deps-check mutant had never gone red either: the test used pnpm 10, which leaves the check off.

The fix moved the box into `lib/box.mjs`, a Node runner started inside the namespaces with no shell. It:

- hides and binds;
- gives `/dev/shm` a fresh tmpfs;
- remounts every other mount `bind,ro`;
- starts the gate through `setpriv` with an empty bounding set and `no_new_privs`.

With no capabilities, nothing can be unmounted.

**Round 2's critical was a hang, not a breakout.** `unshare` ignores SIGTERM while it waits for its child, so a gate that ran past its timeout left `spawnSync` blocked forever: the scorer would hang on an infinite loop in an agent's test.

- Boxed steps are now killed with SIGKILL, and `--kill-child` with `--pid` takes the whole namespace down.
- The same round found that a writable dir reached through a symlink was remounted read-only with the rest, because mountinfo lists real paths. `boxCommand` now resolves them.
- It also found that the host's `/proc` was still mounted, showing every process's command line. The box now mounts its own.

**Round 3's major was the PR body, still describing round 1.** Its two minors were instruments that could not fail:

- the stale-install test passed under pnpm 10 whatever the box did, and now asserts pnpm 11;
- the timeout mutant hung vitest instead of failing, because `run()` blocks the event loop. The test now runs the step in a child with a 20 s outer timeout.

Round 4 was clean, with two nits, both folded in. In the end, 12 mutants each turned a named test red, and the reviewer reproduced all of them independently.

**The CI red was not the box.** CI on `56515d1` failed with ENOENT on `tree/.git/objects` in a #1499 test. Since git 2.47, the maintenance a commit starts runs in the background (the runner has 2.55), and its lock file can vanish while `cpSync` walks `.git`. #1587 had added a guard for one test; the two tests that copy `.git` without it now share it. This container's git is 2.43, which runs maintenance in the foreground, so the race cannot be reproduced here.

**Measured.** On roalson-interests at the pin `67d27a5`, with the implementing commit's files as the arm:

| ----------------------------- | ----- | -------- | ---- |
| unboxed                       | 5/5   | 10/10    | 93 s |

So the box costs no measurable time. 488/488 model-bakeoff tests pass.

**Beliefs corrected on contact:**

- "A mount namespace is a sandbox." It is not, while the process inside holds the namespace's capabilities.
- "A timeout kills the step." It does not, when the step is `unshare`.
- "The test fails without the fix." That held only under the pnpm that `pnpm exec` happens to pick.

**Still open:**

- CodeQL alert 60 ("shell command built from environment values") flags `run()`. It is a false positive: `spawnSync` gets an argv array, with no shell. The operator decides whether it is dismissed.
- On a host whose `/proc` has masked submounts (Docker's default), the kernel refuses the box a fresh `/proc`. The gates then run unboxed and record `gatesSandboxed: false`. That is safe, but such a host never gets a box.
