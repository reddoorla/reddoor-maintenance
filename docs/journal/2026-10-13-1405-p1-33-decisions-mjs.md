## 2026-10-13 — P1-33 cutover prep W2: Operator decisions as files, and `scripts/decisions.mjs` (#1345, reddoor-workspace `0b075ca`)

Plan amendment 2 replaces BACKLOG.md's "Operator decisions" section with one file per ask in the home base. This session built the checker and the format before the cutover (Fri 10-23), so that the migration that day is a confirmed list plus one command, not a design session. The template and a short README are on reddoor-workspace `main` at `0b075ca`; the folder holds no asks yet, and `check` on it fails with `parsed=0`, as the spec says it must.

The script reads a status, an `asked` time, a `from` and a list of refs from each file's front matter, which is the thing the backlog section never had: whether an ask is open is now a field, not an inference. `list --open` resolves each ref of an open ask with `gh api repos/…/issues/N`, which answers for an issue and a PR alike. Only a PR that merged or closed after `asked` flags the ask, so a PR merged just before the ask was written (the #957 shape) does not. A `new` subcommand writes the file and derives `from` from `CLAUDE_CODE_REMOTE_SESSION_ID`, because the amendment says "never typed" and nothing else would have made that true.

**The converter's heuristic, measured against the hand count.** Whether a backlog item is open has never been machine-readable; two earlier classifiers failed their controls, and so did this session's first one. Its first version treated an item as answered if any of nine markers appeared anywhere in it. Run at `eb518e25`, where the amendment counted open items by hand (13, 14, 31, 45, 81, 82, 83, 87, 90), it found all nine plus six more. Review round 1 then showed it hid open asks behind prose: item 97, seven chores still open, read as answered from "is answered" inside sub-item (d), and item 18 from "answered 2026-09-29, except #773", though it ends "Still open". In the other direction, item 24's "**Resolved" was no marker at all. The second version counts only status-shaped markers: a bold `**Answered`, `**Done`, `**Resolved` (and the like) anywhere, or "answered/decided/settled <date>" in the item's lead paragraph. "Still open" or "answered … except" demotes such a match, and so does a bare prose "answered" or "resolved"; both cases make the item AMBIGUOUS, which convert writes as a file and labels, rather than hiding. Round 2 widened the demotion to "stays open", "is open", "open half" and the like, after item 63 ("answered 2026-10-01; rollout is the open half") and item 23 ("vida's call … stays open") read as answered. Convert now prints every answered item with the marker that decided it, so the hand count can check that side as well. At `eb518e25` the confident open list is the hand count's nine plus 1, 8, 10 and 12, exactly the four the amendment proposes closing; 20 more are AMBIGUOUS. At `3d841ae1` (main when this landed): 121 items, 81 answered, 40 written, of which 12 are confident (1, 8, 10, 12, 13, 14, 31, 45, 82, 83, 87, 90) and 28 are ambiguous. None was unparsed, and one number repeats (53, at lines 1655 and 1715). So the cutover's hand count starts from 12 near-certain items and 28 to read, not from 121.

Round 1 also found that `asked` came from the last commit to touch an item's first line, which for a reworded head is the rewrite: item 10 dated 17:35Z from #970 rather than 06:53Z from #958, where it was first asked. Convert now also searches the bold title and takes the oldest hit, and says when the two disagree. Three more round-1 fixes went into `check`. It rejects a calendar-invalid `asked`: `Date.parse("2026-02-30T10:00Z")` rolls over to 03-02 instead of failing. It rejects a file name whose time disagrees with `asked`. And it rejects the `TODO` first line that `new` writes, which it had been accepting, so an unfilled ask would have reached the operator's list.

**What the live run said, and what it got wrong.** `list --open` over the first dry run, with real `gh`, flagged #918, #920 (item 10) and #995 (item 24) as merged after they were asked: the stale flag working on real data. Convert now keeps a `name#N` ref only when `reddoorla/<name>` is written somewhere in BACKLOG.md. It drops bare `#N` refs from any item that names another repo, and lists every dropped ref in its output. Round 2 also found that the PR that wrote an ask flagged that ask stale, because a squash commit's time is a second before its `merged_at`. Four converted items (32, 55, 97, 113) did that.
