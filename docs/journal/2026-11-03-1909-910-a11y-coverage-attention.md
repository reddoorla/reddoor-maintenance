**What was still open.** Three things:

Nothing read a partial run at all, so I built an item for it. Round 1 showed that no real run is partial; see below.

**The change.** `collectA11yCoverageAlerts` raises `a11y-coverage:<site>` ("accessibility scan reached only 1 of 2 routes") when a fresh run (8 days, as the findings) scanned fewer routes than it was given. Its kind is `a11y`, so the ladder already places it at Attention. By the P1-78 rule, coverage loss is the instrument losing its view, and a page a visitor cannot load is uptime's and render's to call Broken. It is registered on the cockpit (so on the card, Needs-you and `/s/<slug>`) and in the digest, so the item ages. `collectA11yAlerts` is unchanged, and its existing "partial run is not measured" test still passes as written.

**Belief corrected in round 1: "1 of 2" could not reach Turso** (true at `15109d25`, and reversed by the answer below). Two of three reviewers found it independently, and the code agrees. The spec's only skip branch (`a11y.ts:599`) writes one of two reasons. Both are in `DECLARED_SKIP_REASONS`, so `scanned = total` on every run. A route that answers an error is not a skip: it is a `route-missing` finding, and `collectA11yAlerts` already raises it. The new item is therefore a guard, and my first changeset and comment described a hole that #1823 had already reshaped.

**The operator's answer (about 12:05pm PT): an undeclared absence stays in the total.** The count in `a11y.ts` now treats an absent-fixture skip as declared only when the site lists it in `reddoor.absentFixtures`. The predicate is the one the `warn` already used (`absenceDowngrade`), so the status and the counts cannot disagree. An existing test pinned the 10-27 reading for the undeclared case: a site with no declaration stored 1 of 1. Under the new rule that case stores 1 of 2, so the test was split. The declared case keeps 1 of 1, and the undeclared case is a new test expecting `warn` and 1 of 2. From the 11-08 sweep, CalTex, Espada and Revogen should each store 1 of 2 and carry the Attention item until their `package.json` lists `/dev/animate-in`. Nothing in this PR touches those three repos.
