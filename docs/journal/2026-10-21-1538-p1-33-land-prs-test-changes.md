# 2026-10-21 — land-prs stops on unnamed test changes (P1-33 next-4(2))

Landed in #1629 (closes #1597), after five dirty review rounds, on the operator's word (workspace `decisions/2026-10-21-1516-p1-33-land-prs-gate-round-five-dirty.md`, answered "land now").

Nothing at landing showed a reviewer that a PR had deleted, skipped or weakened a test. That is where most agent cheating lives (the two-touch review's §4: over 79% of cheats edit tests), and `land-prs` is the one path every landing takes. The script now reads `GET pulls/N/files` and flags each test file that is deleted or renamed, loses an `expect(`/`assert…(` call it does not add back, gains a skip, or has its patch left out by GitHub. A flagged PR lands only when its body has a `Test changes` section naming each flagged file. The gate runs on the first view and again on the head and body that merge, and `--dry-run` prints the list. A flag is meant to be cheap: it costs the author one line saying why.

The replay is the measured result. Over the 191 PRs merged 2026-09-30 to 10-06, it flags 9: #1003, #1016, #1035, #1039, #1078, #1117, #1141, #1143 and #1199. All 9 are in the recommendation's list of 13; none is outside it, none changed no tests, and all 9 would have stopped. It misses 4 of the 13. In #1194, #1070 and #1034, the removed `expect(` lines reappear verbatim elsewhere in the same file, which the spec's "not re-added" wording exempts. #1034 and #1060 change only an assertion's continuation line, `).toBe(false);`, which has no `expect(` on it. Prettier writes long assertions that way, so this gap is real and common; it is filed as #1604 rather than tuned in, because the brief said not to tune the rule toward the 13.

**Belief corrected: the spec's rule is a parser, not a grep.** The first version followed the spec literally: substring `assert`, `.skip\b`, a set of added lines, and the section running to the next heading. It went through five review rounds, and each round's fixes opened rarer cases in the same three heuristics: telling code from strings and comments, recognising a skip or an assertion, and finding a markdown section.

- Round 1: a set let two removed copies be covered by one re-add; `store.todo` false-stopped.
- Round 2: `/* flaky */ it.skip(` slipped past a "comment line" rule.
- Round 3: my bounded generic `<[^()]{0,200}>` backtracked exponentially, about 55 s on 28 `<b>` tags. Its own comment said it could not.
- Round 4: `tests/x.test.ts` → `scripts/x.test.ts` kept a `*.test.ts` name and left vitest's include, unflagged.
- Round 5: my round-4 rename fix `continue`d past the patch scan, so `git mv` plus `it.skip` showed only the rename. That was a regression I introduced.

The final code blanks string contents and drops comments with a one-pass scanner, takes generics out in linear passes, and reads the body with a line scanner. It is the round-3 rewrite that made strings data; before it, `"*/15 * * * *"` in an assertion hid the change.

**Instrument checks.** The add-only fixture passes, and every existing landing test passes with an empty file list. The brief's six mutations, plus 59 more for the later rules, were each applied alone by a script that restores the file and counts failed vitest cases. On the final code 63 of 65 turn a test red. The two survivors are the `{0,8}` chain caps, whose effect inside the 2000-character line limit no timing test separates. Several survivors met along the way were real test gaps: an HTML-comment fixture that never named the file, the string blanking, and a chained modifier on a non-test-API receiver. R3j showed the stricter "`(` right after the name" rule was the wrong one, so it was reverted. The gate passed its own PR: it flagged `tests/scripts/land-prs.test.ts` once, from a raw-line bracket-skip check that reads a string fixture, and the body named the file.

**Defects outside the gate.** CodeQL flagged the `<!--…-->` regex strip as incomplete multi-character sanitization (alerts 51 and 52). It is not a sanitizer, and nothing it returns is rendered, but the comment and tag strips became `indexOf` and one-pass scans anyway. That also removed the quadratic case round 5 measured (347 ms on 64 KB of `a<!--`, now under 35 ms).

**Honest accounting.** Rounds 2 to 5 were mostly spent repairing the previous round's fixes, and the round-5 fixes landed unreviewed on the operator's call. Folding minors instead of filing them kept each round's diff growing. A blunter rule, flagging any removed line in a test file that mentions `expect`/`assert`/`skip`, was offered as option (c) and not taken. Reviving it means trading this parser for more flags on most PRs that touch tests.
