# 2026-10-26 — P1-78a: `fleet_daily`, one row of counts per night

Landed in reddoorla/reddoor-maintenance (this PR). Brief: workspace `briefs/2026-10-26-p1-78a-fleet-daily.md`; plan: `plans/2026-10-26-cockpit-for-the-team/plan.md`, PR 1 of 8.

**Why.** Turso kept only current state: `site_health` is overwritten nightly, `digest_state` forgets a resolved item, and `fleet_events` keeps 30 days. So the plan could not say how often any signal fired, and the overview's trends and the 90-day dependency rule had nothing to read. Every night this table does not exist is a night the trends can never show, which is why it lands first.

**What it is.**

- **The table.** `fleet_daily` (migration 0049) has one row per night, `night` as its key and `counts` as JSON of cumulative totals. Its `cockpit_version` triggers come in the same migration.
- **The deps list.** The deps audit now also stores which packages are a major behind, as `name@installed-major` (`site_health.deps_behind_packages`, 0050). The list has a stamp (0051), and both are written under the same guard as the counts, so a failed frozen install keeps the stored list.
- **The writer.** A new workflow, `fleet-daily.yml`, runs on `workflow_run` of `fleet-nightly`. It holds only `actions: read` and `contents: read`, plus the existing Turso secrets.
- **What the writer reads.** It reads the conductor job's own `NIGHTLY` lines and summary from the log, for the attempt being written. The conductor's `skipped` step output is not visible to a `workflow_run` consumer, and a failed dispatch creates no run to count.

**Five review rounds, all of them earning their keep.** Rounds 1 to 4 were dirty, with eight reproduced majors and one critical. Round 5 was clean. Each defect was a way a real night's sequence of runs writes a wrong row:

- **Round 1, critical.** The 12:19am PT fallback re-dispatches a step the 11:07pm clock's dispatch failed on. Its summary says `total=8`, so it read as a full night and overwrote every step with `skipped`. "Re-run failed jobs" does the same. A full-plan run whose guard skipped anything now merges into its night.
- **Round 1.**
  - An `--only fleet-security` re-run nulled the lists of sites it failed to re-read. Readings now count from the night's own run start.
  - Running totals (events, PR merges) could count the seconds between `now` and the read twice. Both windows now end at `written_at`.
- **Round 2.**
  - A merge refreshed the deps lists but not coverage.
  - A failed re-read during a merge replaced the night's good block with null. A merge now never trades a stored value for a null.
- **Round 3.**
  - Coverage stored a measured 0 for a step still running at the write. It is now null with a reason.
  - "Re-run all jobs" on a night days old replaced it. That made a cumulative total go down, and stamped the old night with later stamps. Such a run now merges steps only.
- **Round 4.**
  - A gap night (its write failed) re-run after a later night got a full write of later numbers. It now writes nothing, and trends read the gap as missing.
  - A guard-skipped step's coverage read as 0. It is now null with a reason.

**Beliefs corrected on contact.**

- **The night is keyed on the run's `created_at`, not its `run_started_at`.** A re-run keeps `created_at` and gets a new `run_started_at`, so keying on the start would name a morning re-run as a new night (mutation 1).
- **The brief's mutation 2b as first written (`<` to `<=`) is not a defect.** A re-run taking its own earlier row as the base still gives a consistent running total. The real wrong-row mutant takes the base from the oldest earlier row, and needed a three-night test to go red.

**Measured.**

- 30 mutants: the brief's 14 (2 split into 2a and 2b), plus 16 from review rounds. The table is in the PR body.
- `tests/fleet-daily/write.test.ts` holds 41 tests.
- Two tool defects turned up on the way:
  - `scripts/mutate.mjs`'s #1657 sync runs from the repo root on kit 3, so every sidecar is refused at baseline (#1768). The runs here used `--in-place` in this PR's own worktree.
  - `tests/scripts/dropbox.test.ts` fails in the cloud container on `main` too (its proxy).

**Accepted, filed as #1769.**

- a guard-skipped step's result is never filled;
- an evening `--only` run lands on the previous night (the brief's 24-hour rule);
- a conductor that dies before its summary writes no row;
- a `(#N)` direct push counts as a merge;
- a failed `fleet-daily` run files no issue (no `issues: write`);
- a queued run can be cancelled by concurrency;
- the first-parent walk's head, which matters only with merge commits.
