**Why.** #1612's cross-check believes `pnpm audit` over an empty Dependabot answer. Dependabot's list is fetched with `state=open`, so an alert an operator dismissed is absent from it, while pnpm still reports the advisory. The cross-check then brought the advisory back. That shows only once the site's other lockfile alerts are gone, so a site could turn red on the night it otherwise went clean.

**What.** When the cross-check finds something, the audit reads the repo's `dismissed` and `auto_dismissed` alerts. It leaves out each pnpm advisory one of them names, by package and GHSA or CVE, and never by title, since the two sources word titles differently. The left-out advisory's count goes too, and the summary says how many were left out. A dismissed list that cannot be read leaves nothing out.

**Measured.** The dismissed list is read only on a cross-check that found something. Last night that was no site: erp-industrials' real `pnpm audit` was clean. So tonight's run reads it nowhere, unless a lockfile changed.
