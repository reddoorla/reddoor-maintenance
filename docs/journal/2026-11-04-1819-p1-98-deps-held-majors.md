# 2026-11-04 — The deps audit stops counting majors the fleet holds on purpose (P1-98)

Where it landed: this PR (branch `claude/p1-98-deps-held-majors`), claimed in https://github.com/reddoorla/reddoor-maintenance/issues/1950. The brief is workspace `briefs/2026-11-04-p1-98-deps-audit-held-majors/worker-brief.md`; the ruling behind the `@types/node` half is workspace `decisions/2026-11-04-1736-erp-majors-base-and-node26.md` 2(a).

**Why.** All 17 maintained sites sat under the cockpit's Watch as "N packages a major behind" (`pm-cockpit` printed `watch=17` at 9:49am PT). Of 59 package-site entries in `site_health.deps_behind_packages`, 18 were `typescript@6` and 17 `@types/node`. TypeScript 7 is held by the org preset's `allowedVersions: <7.0.0` because `svelte-kit sync` crashes on it, and type definitions follow the runtime, so neither is drift anyone is meant to act on. They hid the entries that are.

**The rule.** A major-behind package is held, not behind, for one of two reasons only. (1) The preset caps it, `latest` is outside the cap, and the site is on the newest major the cap allows; only `typescript` is eligible. (2) It is `@types/node` and its major equals the site's runtime major, from `.nvmrc`, else `engines.node` when that pins exactly one major. Anything unknown counts.

**Read, not mirrored.** The preset is fetched once per process from `raw.githubusercontent.com`, and only for a site whose own Renovate config extends it. A mirror would have needed a disagreement test that reads the preset over the network anyway, and between maintenance CI runs a lifted cap would go on holding. Reading it means a lifted cap stops holding the next night. The range is evaluated by `pnpm view 'typescript@<7.0.0' version --json`, so npm's semver does the work and no dependency was added (the lockfile is the dep worker's today, reddoorla/reddoor-maintenance#1944).

**Held stays visible** in a new `site_health.deps_held_packages` column, written beside `deps_behind_packages` under the same guard and stamp. A log line would last only as long as Actions keeps it, and the column shows the entries clearing when Node 26 lands.

**Measured.** The live preset read gives `typescript → <7.0.0`; the registry's newest allowed is 6.0.3; `typescript@6` holds and `@5` does not. Projected onto today's rows, assuming runtime 24, the entries drop from 59 to 28. Vineyard Custom Homes, Revogen and 1836dig leave Watch.

**Beliefs corrected on contact.**

- **"35 held" was 31.** Four sites (LA Homelessness Youth, LA Homelessness Initiative, Sonder, CalTex) run `@types/node@25` on Node 24. The brief's own rule, which mutation 2 pins, counts those: types ahead of the runtime are drift, and the fix is to put them back on 24.
- **GitHub code search said 7 repos have a `.nvmrc`.** Reading the 14 site repos I could reach directly found one in every one, all on Node 24. Most sites' `engines.node` is `>=20`, which pins nothing, so `.nvmrc` carries the rule.
- **The preset holds two more packages**: `@libsql/client <0.9.0` and `cookie <2.0.0`. They are not covered, per the brief, and the operator decides. Neither appears in any site's list today: `@libsql/client` is 0.x, which `majorOf` never counts as a major behind.
