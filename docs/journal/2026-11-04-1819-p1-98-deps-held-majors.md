# 2026-11-04 — The deps audit stops counting majors the fleet holds on purpose (P1-98)

Where it landed: this PR (branch `claude/p1-98-deps-held-majors`), claimed in https://github.com/reddoorla/reddoor-maintenance/issues/1950. The brief is workspace `briefs/2026-11-04-p1-98-deps-audit-held-majors/worker-brief.md`; the ruling behind the `@types/node` half is workspace `decisions/2026-11-04-1736-erp-majors-base-and-node26.md` 2(a).

**Why.** All 17 maintained sites sat under the cockpit's Watch as "N packages a major behind" (`pm-cockpit` printed `watch=17` at 9:49am PT). Of 59 package-site entries in `site_health.deps_behind_packages`, 18 were `typescript@6` and 17 `@types/node`. TypeScript 7 is held by the org preset's `allowedVersions: <7.0.0` because `svelte-kit sync` crashes on it, and type definitions follow the runtime, so neither is drift anyone is meant to act on. They hid the entries that are.

**The rule.** A major-behind package is held, not behind, for one of two reasons only. (1) The preset caps it, `latest` is outside the cap, and the site is on the newest major the cap allows; only `typescript` is eligible. (2) It is `@types/node` and its major equals the site's runtime major, from `.nvmrc`, else `engines.node` when that pins exactly one major. Anything unknown counts.

**Read, not mirrored.** The preset is fetched once per process from `raw.githubusercontent.com`, and only for a site whose own Renovate config extends it. A mirror would have needed a disagreement test that reads the preset over the network anyway, and between maintenance CI runs a lifted cap would go on holding. Reading it means a lifted cap stops holding the next night. The range is evaluated by `pnpm view 'typescript@<7.0.0' version --json`, so npm's semver does the work and no dependency was added (the lockfile is the dep worker's today, reddoorla/reddoor-maintenance#1944).

**Held stays visible** in a new `site_health.deps_held_packages` column, written beside `deps_behind_packages` under the same guard and stamp. A log line would last only as long as Actions keeps it, and the column shows the entries clearing when Node 26 lands.

**Measured.** The live preset read gives `typescript → <7.0.0`; the registry's newest allowed is 6.0.3; `typescript@6` holds and `@5` does not. Projected onto today's rows, assuming runtime 24, the entries drop from 59 to 28. Vineyard Custom Homes, Revogen and 1836dig leave Watch.

The audit held `typescript@6` under `<7.0.0` in each of these cases, even though Renovate would offer 7:

The check is now the other way round. A rule is ignored only when it carries an exact-name list without TypeScript in it. Every preset the site extends is read in Renovate's order, and nested presets are followed. Builtins count as rule-free. A preset outside `reddoorla/.github`, an unreadable one, `ignorePresets` or nested rules each leave the cap unknown.

## Session 2: rounds 3 to 5, and landing

Session 2 (https://claude.ai/code/session_013FT5PDQDR2RgzFonsnh6Nq) ran rounds 3, 4 and 5. Each round used three fresh Opus reviewers, every one on its own copy of the worktree. Every round was dirty, so the PR reached the five-round stop.

**Round 3: two majors on Renovate semantics, three majors on tests.**

- **Legacy keys.** Renovate 44's `package-rules-migration.ts` renames legacy keys (`paths`, `managers`, `packagePatterns`, …). It also ORs `matchPackagePatterns`, `matchPackagePrefixes`, `matchDep*` and `exclude*` into the name lists. So `{matchPackageNames:["eslint"], matchPackagePatterns:["^type"]}` reaches TypeScript. The audit had trusted the exact-name list.
- **Case.** Renovate matches names case-insensitively (minimatch `nocase`), so `"TypeScript"` reaches TypeScript.
- **Tests.** The tests lens found 7 survivors that matter:
  - the field mapping of the new column;
  - the production reader `fetchOrgPreset`, which had no test at all;
  - a reader fake that ignored the repo, which made the foreign-preset test hollow.

  Each got a test that goes red under its mutation.

**Round 4: four more false holds, so the check changed shape.** The four were:

- extglob names (`@(typescript|eslint)`);
- top-level keys Renovate migrates into `packageRules` (`devDependencies`, `packages`, `pathRules`);
- `extends` inside a packageRule;
- `extends` under a manager block.

Each round had found shapes that rounds before it had not modelled. So instead of chasing them one by one, I inverted the rule:

- an exact name is now an allowlist, a string shaped like an npm package name;
- any `extends`, `ignorePresets` or `packageRules` below the top level, or any legacy rule key, makes the cap unknown.

The positive control mattered here: a live site extending `renovate-config` plus `renovate-staging-flow` still read `typescript → <7.0.0`. In round 5 the production lens ran the real fetch and the real `pnpm view` against the actual configs of 20 reddoorla repos, and all 20 still hold. Round 4's tests lens ran 103 mutations and found no major. One finding was useful anyway: the self-extending-preset test hung on memoised microtasks instead of going red when the depth guard was removed. A bounded preset chain now goes red in 25 s ("expected 51 to be ≤ 10").

**Round 5: one major, then the stop.** Renovate's `detectConfigFile` calls `getConfigFileNames()` with no platform, so on GitHub it reads `.gitlab/renovate.json{,c,5}` too. Maintenance's `RENOVATE_CONFIG_FILES` left them out, and its comment said the opposite. That list predates this PR, but held/behind now depends on it. No live site has a `.gitlab/` file. I wrote the stop up as workspace `decisions/2026-11-04-2234-p1-98-round-5-gitlab-config.md`. The operator chose to fix and land without a sixth round (2:38pm PT). The list fix corrects the base-branch audit too.
