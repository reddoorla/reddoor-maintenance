# 2026-11-09 — form-e2e submits a declared form off /contact, and only finds an undeclared one

Landed in the PR that carries this file, with reddoorla/williamson-construction-co's `/health` declaring `forms.paths: ["/join-the-team"]`.

The nightly `fleet-form-e2e` looked for a form only at `CONTACT_PATHS` (`/contact`, `/`). Run 42579511593 on 11-09 printed `form-e2e skip williamson-construction-co / no contact form (n/a)`. Measured by curl that day: `/join-the-team` answers 200 with one `<form>` and an email input, `/contact` and `/` have none, and `/health` declares `forms.testMode: true`. The 2026-10-20 kit-3 entry records a testMode submission to that form coming back `success` through central ingest. So a working form was written down as "no form" every night. williamson-homes, measured the same way, has no `<form>` on any of its 10 sitemap pages: its n/a is true.

**The first design was wrong, and review caught it.** I first had the probe walk up to 15 sitemap routes and submit the first email form it found, skipping any page whose form had an absolute `action`. A live run passed Williamson (2:07pm PT). The review's critical: `forms.testMode` vouches for the contact action only, and the absolute-action guard misses a same-origin Netlify Forms page, a JS-submitted HubSpot or Formspree embed (the probe's own submit listener would even mark it), and a route that redirects to an applicant-tracking site. Any of them would take the probe as a real lead. **Belief corrected on contact:** the declaration covers a form's server action, not a page, and the probe cannot see the server action from outside.

What landed instead: the site names the routes whose forms forward the marker in `/health` `forms.paths`, read strictly (a non-empty array of root-relative paths, or ignored whole). The probe submits there only when no contact route has a form. When none of those has a form either, it looks at the sitemap routes without filling or clicking anything. A form found there gives `form at <path> is not declared in /health forms.paths — probe refused`: nothing is written, it is listed UNCOVERED, and the workflow names it in its own warning. So `no contact form (n/a)` keeps meaning the site has no form, and now says how many discovered routes it looked at. A Turso column was the other option; the site's own `/health` was chosen because the site's code is what makes the claim true, which is the same reason `testMode` lives there.

Live against production at 2:33pm PT, before the site change: williamson-construction-co `form at /join-the-team is not declared in /health forms.paths`, williamson-homes `no contact form (n/a) — none at /contact or /, nor on 8 discovered route(s)`.

Mutations, each run against the new tests: declared paths skipped (2 red), a discovered form submitted (2 red), `forms.paths` read laxly (1 red), the discovery look removed (3 red), the workflow's UNCOVERED regex without the new phrase (1 red).

Review round 2 (Opus, three lenses) found two majors, both folded in. First, the strict reader let `"/\\evil.com"` and `"/\t/evil.com"` through, and Node's URL parser resolves both to `https://evil.com/`. Nothing compared the page's final URL with the site either, so a declared route that redirected to an applicant-tracking host would have been filled and submitted there. A declared path must now match `^/(?!/)[A-Za-z0-9\-._~/%]*$`, a list holds at most 5, and `findFormPath` refuses any route whose page ended on another host (apex and `www` count as one). A live fixture that 302s `127.0.0.1` to a real form on `localhost` posts nothing. Second, a declared route that 404s would have been written n/a, clearing the site's last pass. It is now a failure that names the declared paths, with nothing sent. Mutations: guard removed (2 red), lax characters (1), no cap (1), missing-is-n/a (2). The turnstile runbook's four line citations into `form-e2e.ts` moved with the code and are renumbered. `tests/scripts/dropbox.test.ts` fails one case in this container on `main` too (it re-executes through `HTTPS_PROXY`), so that failure is not this change.

Review round 3 (Opus) found one major, and round 2's own guard had introduced it. The off-host check lives in `findFormPath`, which also walks the contact routes. So a site whose `/contact` 301s to another domain, which used to be followed and failed as an off-host POST, now read `no contact form (n/a)` and would have cleared its CRITICAL. The reviewer reproduced it with `redirectAt: "/contact"` (`discoveredLooked: 0`, nothing posted). `findFormPath` now reports the first foreign host it landed on, and the runner turns that into a failure naming the host, with nothing sent. Mutation: drop that branch, and the live test goes red. The four minors are filed as #1999 (one load before a declared-missing failure), #2000 (the case-sensitive email selector), #2001 (a JS redirect after domcontentloaded) and #2002 (declared paths unchecked when /contact has a form). Round 2's minor is #1997.

**#1983 landed first** (`1b62191`), so this PR merged `main` and took the work its body promised the second lander. Four hunks of `form-e2e.ts` conflicted. Both `FormsHealth` fields and both `readFormsHealthOnce` spreads are kept. The off-site guard now sits in front of main's new `pageHasContactForm`, and the runner keeps this PR's wrapper. The turnstile runbook's citations are renumbered once more. `lookForContactForm`, #1983's check behind a `forms.none` claim, now also looks along `formDiscoveryPaths` after `CONTACT_PATHS`, so a `none` claim over a form on `/join-the-team` is not believed. A new live test names the form, and dropping that look turns it red. Its n/a reports how many routes it looked at. **Test change:** #1983's "looks, finds no form, and returns n/a" pinned the exact n/a shape, which now carries `discoveredLooked: 0`.

Review round 4 (Opus) found one major, folded into the same merge. The off-site failure for a redirecting `/contact` fired before the declared routes were tried, so a site whose `/contact` 301s to a booking host but which declares a working `/get-a-quote` would have failed without that route being loaded. It now runs after them, and its detail says "no contact or declared route had a form", which is what was actually checked. A live test (`/contact` redirects off-site, the declared `/join-the-team` passes with one POST) goes red when the order is reverted.
