# 2026-10-21 — fleet-config-drift: a shrinking roster, a disabled Renovate job, a lost filing

**Where it landed:** branch `claude/1607-config-drift-blind`, closing #1607. Brief: the workspace's `briefs/2026-10-21-last-three-blind-gates.md`, from the P1-33 next-5 sweep (#1595).

**Why.** The sweep found three ways the weekly drift run read a bad week as green.

1. **The roster.** `selectFleetSites` visits only rows whose Status is in the vocabulary. With 3 of 4 rows on the retired `maintenance` (the restored-backup case `site-status.ts` names), the drifted repo among them, the run printed `drifted=0 clean=1 skipped=0 total=1` and passed.
2. **The Renovate job.** `renovateActionGaps` checks strings, so `if: false` on the job, with pins, auth and cron intact, read `CLEAN`.
3. **The filing.** `gh issue create` returning 502 under `continue-on-error` left the job green, and the drift appeared nowhere for a week.

**What changed.**

1. **The roster.** The selection rule itself is untouched: every fleet sweep shares it, and it is right not to visit a row whose Status it can't read. Instead `fromTursoDb` hands the dropped rows (`rowsWithUnrecognizedStatus`) to a callback, and `sync-configs` reports each as `SKIPPED <repo> status "maintenance" is not in the vocabulary…`. They now count toward `total`, keep a drift issue open, and past half the roster red the run through the gate that already existed.
2. **The Renovate job.** A constant-false `if:` on the job, or on a step that uses one of the three required actions, is a gap. That covers `false`, `0`, `''` and `null`, bare, quoted, in `${{ }}` or folded (`>-`). A real condition is still the site's business; the template carries none.
3. **The filing.** A last step reds the run, naming the drift, when the open step failed. It sits after the outage pair, so it files no false "sweep failing" issue. The open step now fails only when no issue could be created, since a missed comment on an open issue loses nothing.

**Known-good.** The 2026-10-18 run printed `drifted=15 clean=0 skipped=0 total=15`. I fetched those 15 repos' `renovate.yml` read-only (a sparse, shallow git clone of the one file). All 15 have 0 gaps under the new rule and carry no `if:` at all. Whether any production row sits on an unrecognized Status today needs a production read, which this session's permissions refused; the cockpit already shows such a row as a watch item.

**Belief corrected on contact: a line regex is not a YAML reader.** My first push matched `if:` lines with a regex. Review round 1 showed it would have called `if:` followed by `github.repository_owner == 'reddoorla'` on the next line (one plain scalar continued) constant-false, because the regex saw an empty value. Any gap makes `sync-configs` heal the file by overwriting it, and makes self-updating open a PR, so the site's real guard would have been deleted. The same regex matched `if: false` inside a `run: |` body, and missed `if: >-` over `false`. No YAML parser is a runtime dependency of the package (`js-yaml` is dev-only), and adding one to fix a check is not this PR's call. My second version, a one-pass scanner guessing structure from the nearest shallower line, failed round 2 the same way. It flagged a site's own `sidecar:` job with `if: false`, an `if` key inside a required step's `env:` map, and `${{ 'false' }}`, which is a non-empty string and so truthy in Actions. Each would have overwritten a file over a job that runs. The third version is built the other way round: it anchors on the `renovatebot/github-action` step, and reads only `if:` keys at the exact column of that job's own keys, or of a required step's own keys in that job. Block bodies, nested maps, other jobs and a site's own steps all sit at other columns or outside those ranges, so none can match. What it cannot read, such as a quoted `"if":` key or a flow mapping, is a miss. A miss leaves today's blind spot; a false gap deletes a site's code. Of the two, only the miss is acceptable here.

**Tests.** The roster case runs the real `--fleet turso` path on a migrated `file:` database with pre-made checkouts. Mutations: `if: false` reading `CLEAN` again, round 0's empty-value reading, not stepping over block bodies, counting every step, the callback discarding the rows, the predicate never matching, dropping its `url` guard, dropping the last step, and a missed comment redding the step each turn a test red.
