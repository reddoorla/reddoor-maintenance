# 2026-10-24 — The drought measure counts only Renovate merges into the default branch (#1686)

The worker for the operator's answer (a) to reddoor-workspace `decisions/2026-10-24-1413-drought-measure-staging-merges-1686.md`, brief `briefs/2026-10-24-drought-measure-base-ref-1686.md`. Landed in the PR that closes #1686.

**Why.** A merge into `staging` has reached no visitor. On the staging flow a major reaches `main` only through the human promotion PR, which is not a Renovate PR, so a staging-bound major should never count as delivery on its own. `renovateMergeWindow` used to read only `head.ref`. It now compares each merged `renovate/*` PR's `base.ref` with `base.repo.default_branch`, both on the same list item, so the cost is still one request per repo and there is no roster field. Merges into another branch are kept apart as `offDefault`, not thrown away.

**The concrete input.** A recent `renovate/staging-sveltejs-kit-3.x` into `staging`, plus a `renovate/main-all-minor-patch` into `main` 30 days ago, now reads `drought`, 30 days. Before, it read `delivering`, 2 days. A feature merge into `main` still reads `delivering`. Five mutations, each red: dropping the base filter (6 tests), comparing against `staging` (6), hardcoding `"main"` instead of the default branch (2), dropping the off-default list (3), and counting every off-default head instead of feature heads only (1). The full suite passed: 11,062 tests.

**Defect the review found: reddoor-website.** Its Renovate config targets only `staging` (`baseBranchPatterns: ["staging"]`, unprefixed names). Under (a) none of its merges count, so the first draft printed it as `unmeasured` with "this repo has never merged a feature-update Renovate PR". That is false: it merges one most weeks, into `staging`. This was the #1673 fixture's known-good control. The window now carries the off-default merges, and `renovateOutcome` says "N feature-update Renovate merges went to a branch other than the default …" whenever there are any. The decision file's consequence ("can read as a drought") does not hold for this repo. It will never read drought or delivering until its promotions are measured. That gap is the operator's to weigh; the measure now states it truthfully every night.

**Tried and abandoned.** The first draft threw when a merged PR had no readable base. Round 1 pointed out that the caller turns any throw into a `gap` row. That breaks the "a measurement never gaps" contract and makes the sweep exit 1. An unreadable base is now counted off-default. Round 2 found that a staging security merge alone (mantis-landscaping) would have replaced the true "never merged" reason with the off-default note. Only feature heads earn the note now.
