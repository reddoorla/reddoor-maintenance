# 2026-11-24 — The Recently lane tests stop reading the real clock

Landed in: the PR from `claude/clock-free-recently-lane` (closes #2269).

**What broke.** On `main` (`8089efc`), `cockpit/tests/legacy/recently-lane.ssr.test.ts` > "keeps the lane at its cut of 20 rows across the recent events and the deploys" failed with `AssertionError: Target cannot be null or undefined.` (`html.match(/Deploy published/g)` was `null`). It made `build` red on every open PR, e.g. #2256. The C1 tests (P1-87 PR 9, #2190, landed 2026-11-20) pass deploys through the helper `renderSitesHtml`, which called `buildSitesView(model, new Date(), …)`. `recently()` keeps a deploy only if `ts >= now − RECENT_EVENTS_DAYS (7) days`. That test's five deploys are dated 2026-11-17T00:00 to 04:00Z, so they fell out of the window at 2026-11-24T00:00Z, 4pm PT on 11-23. The weekly time-travel run (+90 days) had been red on it since it landed; its scheduled run filed #2269 at 2:34pm PT on 11-23, before the real clock reached it. The sibling test "shows a deploy with no merge before it" was the next one due: its deploy at 11-17T17:05Z would have dropped out at 9:05am PT on 11-24.

**The fix.** `renderSitesHtml` takes an optional `now` (default `new Date()`, so its other callers keep their behaviour), and `modelWith` does too. The C1 block passes `NOW = 2026-11-17T18:00Z`, 55 minutes after its newest fixture (the 17:05Z deploy), which is the pattern the R2-C1 block below it already followed. The window, the assertions and production code are unchanged.

**The sweep, and proving the instrument first.** The repo already has the instrument for this: `REDDOOR_TIME_TRAVEL_DAYS` with `tests/time-travel-guard.test.ts`. At +365d over all of `cockpit/tests` with the guard included, the guard passed and the run caught the known failure, so the run was live. It found exactly two failures, both in this file. Its known gap is any file that returns to the real clock: 17 files in `cockpit/tests` call `vi.useRealTimers()`, and 19 call that or `vi.restoreAllMocks()`. I ran all 19, plus this file, under `faketime -f '+365d'`, which moves the clock the process itself reads. They pass, and only this file failed. After the fix, this file passes on the real clock, at +365d through the harness and under `faketime +365d`, and all 1680 cockpit tests pass on the real clock.

**Mutations.** M1: move `NOW` to 2027-11-17. Two tests go red: the cut of 20 and the lone deploy. So `NOW` reaches the window. M2: make the helper ignore `now` (`new Date()` again). The cut-of-20 test goes red. Neither mutation remains in the branch.
