# 2026-10-26 — P1-76: removing the tests that only restate the code

Landed as ten PRs, one per area: recipes, cli, build, audits, dashboard, cockpit/tests, db, blux, webhook and configs. The audit is in reddoorla/reddoor-workspace at `audits/2026-10-26-maintenance-test-audit/`.

The operator asked how much of this suite only restates the code. The audit classed 2,605 tests in 159 of 673 files and put about 3.6% in the tautological classes (T1–T5). It said deleting them would lose nothing, on the strength of 452 mutants where breaks aimed at those tests left them green 53 times in 57. He picked batches A, B and C: 90 tests, 829 lines.

**The audit's central claim did not survive contact.** The agents that made the removals also wrote the probes for them: 92 mutants, 0 losses, in all 14 areas. Then a fresh reviewer per branch, shown only the diff, named the regression each removed test would catch and wrote it as a mutant. Of those 90 mutants, 83 went red at main against the removed test. In 29, nothing else in the suite caught it, in 12 of the 14 areas. The audit's 53-of-57 came from mutants chosen by the agents that had just called the tests tautological, so they aimed beside the assertions. A probe chosen by the party that wants a test gone measures its expectation, not the test.

**What the losses were.** Almost all were a "constant restated" whose constant is a shipped value:

- `LIGHTHOUSE_CATEGORIES` losing `accessibility` (the #1609 defect);
- the frozen_page Prismic model's fields, six mutants;
- `FETCH_TIMEOUT_MS` going from `30_000` to `30`;
- prismic-ci's `bin.ts` action wired to the wrong command;
- the drift sweep's timeout deleted;
- the Lighthouse default and named exports diverging;
- two cockpit CSS rules;
- the report routes regressing to `rec…` ids.

26 tests were restored, each proved by re-running its loss mutant red on the restored branch. That includes the named guards the reviewers found (#348, #389, `00a63eca`, #630, the chosen-dispatch guard). Four areas, scripts, model-bakeoff, alerts and fleet, lost every removal and got no PR.

**What landed: 43 tests, 484 lines, about 0.26% of the suite.** Each is a duplicate whose twin still runs, an echo of a mocked stub, or a test shown unable to fail. A round-2 review of all ten diffs found no blocker, critical, major or minor finding. It left three nits, each judged acceptable as is: the stage-cost negative control, the cockpit reuse-parity test, and the db archived pairing.

**Instruments.** `scripts/mutate.mjs` passed on a known-good test before any verdict counted: two real mutants went red and an equivalent rewrite survived. Its own throwaway worktree could not judge any test touching the cockpit, because `cockpit/.svelte-kit` is generated: 7 audit batches were stillborn and were rerun `--in-place` after `svelte-kit sync`. #1747 fixed that in `mutate.mjs` during this session. One of my restore-proof sidecars named the wrong test file and reported two CSS mutants as surviving; pointed at the restored file, both went red.

**Belief corrected:** "a test that restates a constant catches nothing." It catches exactly the change of that constant. Whether that is worth a test depends on whether the constant is a shipped value. For a config, a schema, a workflow step or a wire it is the only spec there is, so it is a guard by kind.
