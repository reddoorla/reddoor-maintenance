# 2026-10-21 — OD 18 step 3: the browse panel merges into Sites

**Where it landed:** this PR (reddoorla/reddoor-maintenance, branch `claude/od18-sites`), step 3 of #672, after the Setup band (#1580). The operator's answer of 2026-10-20 (workspace `reviews/2026-10-20-cockpit-brief-markup/markup.md`, Q4): merge the browse panel into `/fleet`, which becomes Sites, and keep `/` a start page without the per-site cards.

**Why.** The panel on `/` and the table on `/fleet` were two inventories of the same rows. The brief's words were: "The panel and the table are two inventories of the same rows." The operator picked the merge.

**What a visitor sees.**

- **Sites (`/fleet`) is the one inventory.** Every table row carries its site's card health in a new Health column:
  - the tier pill and the chips (with NEW and WORSE badges, accept tokens and accepted conditions);
  - the submissions badge;
  - the onboarding score;
  - a11y, deps, sec and the deploy state;
  - the Setup checklist.

  The scores and the audit date were already table columns. Above the table, the signal chips (`vulns`, `lighthouse`, …, `no-analytics`, `url-unresolved`) filter the rows in the browser, as they filtered the cards. A row whose site has no card, an archived or building site, shows only under "all". The page is titled Sites. The Recently and Archived lanes moved here from `/`.
- **`/` keeps the start page.** That is the verdict bar with ↻ Audit fleet, Needs-you, the Setup lane from step 2, Cardless and the Inbox lane. Its meta line links "Sites →".
- **Trigger Renovate left the cards.** The brief notes that it "already lives on `/s/:slug`", and that page's DOM tests cover it.

**How the evidence followed the cards.**

- **The legacy suite.** 66 of its tests read card markup off `/`. A script pointed the body of each failing test at a new `renderSitesHtml(model)` shim, which renders Sites for a cockpit model. That cleared 46. I rewrote the other 20 by hand:
  - assertions about the Lighthouse cluster now read the table's score columns and headers;
  - the audit time now reads the Last audit column;
  - verdict assertions stay on `/`, while row assertions go to Sites;
  - the two Trigger Renovate tests now pin that Sites carries no trigger;
  - the order tests drop the fleet panel from `/`.
- **The filter DOM test** moved to `cockpit/tests/fleet/sites.dom.test.ts`. It gained a case for a cardless row.
- **The `/` snapshots** lost their cards. The `/fleet` snapshots gained the chips and the Health column, each case now with a real sites view.
- **New Sites snapshots.** Every `/` case also runs through Sites (`cockpit/tests/fleet/sites.ssr.test.ts`), so the card markup that left `/` (badges, stuck items, deploy states, hostile strings) is still pinned. These snapshots were written after the move, not under parity.
- **The stylesheet.** Shared pill, chip, badge and filter styles moved to `cockpit/src/lib/cockpit/health.css`. The filter class is now `signal-filters`, because `/fleet`'s GET form already used `filters`. The card-only styles went with `BrowsePanel`.

My first mutation 7 left an unclosed `{#if}`, so the page failed to compile and the run reported "40 passed" over files that never loaded. Removing the row cleanly is the one counted.

**Cost.** `/fleet` now reads the cockpit model as well as the table's sites, so `listSites` runs twice per load, plus the reports and submissions reads `/` makes. One page load is about 6 Turso reads instead of 1.
