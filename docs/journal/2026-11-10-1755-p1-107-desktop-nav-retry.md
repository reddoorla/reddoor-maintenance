# 2026-11-10 — P1-107: a desktop navigation that throws gets one retry

Landed in [reddoorla/reddoor-maintenance#2014](https://github.com/reddoorla/reddoor-maintenance/pull/2014) (issue [reddoorla/reddoor-maintenance#2012](https://github.com/reddoorla/reddoor-maintenance/issues/2012)).

The 11-10 nightly (run 42767680711) logged `reddoorla.com/ [firefox]` as failing on desktop, with no status. The cockpit raised Reddoor to `broken`. That morning Firefox and Chromium each loaded the page twice: 200, no errors. Mobile has had one retry since the same false Broken on 11-03. The desktop loop had none: its bare `catch { ok = false; }` made one thrown navigation a fail.

The desktop loop body moved into `probeDesktop`/`probeDesktopOnce`, mirroring `probeMobile`. The retry runs only when `goto` itself threw (a `navigated` flag, not "anything in the try threw"). It runs once, in a fresh context, at `RETRY_PAGE_TIMEOUT_MS` (10 s). Chromium's page facts now come back from the attempt that counts, instead of being written into the loop's variables partway through the try.

**Budget, measured.** The audit step ran 21.7 to 24.9 min over the 10 nightlies from 11-02 to 11-10, against 75. One site whose 15 sampled routes all hang costs about 42.5 min today. The retry adds 15 × 3 × 10 s = 7.5 min, so the step lands near 73 min, before any time Lighthouse spends on that site. Two such sites already break the budget without this change. I did not measure how long Lighthouse spends on a hanging site, so the last 2 minutes of headroom is unproven.

**Mutations.** Five mutants, all red (`tests/audits/desktop-load-retry.mutations.json`).

- My first d4 (reuse the first context) closed only the page and reused the context. The retry then hung in Chromium until the 60 s test timeout, and `mutate.mjs` filed it as stillborn rather than red.
- So reusing a context after a dropped connection does not just carry state: in this fixture it hangs. That is a better reason for the fresh context than the one I had.
- The committed d4 keeps the first context open and reuses it, and the context-count assertion catches it.

  - The runner's docblock no longer says it "never throws past the audit". A crashed browser throws, and since this change it throws on the same route when it dies during the first navigation.

  - The tests use Chromium for the non-chromium path, not real Firefox or WebKit. [reddoorla/reddoor-maintenance#2018](https://github.com/reddoorla/reddoor-maintenance/issues/2018).
