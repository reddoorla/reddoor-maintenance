# 2026-11-03 — bot-rsvp: Sonder's seven bot RSVPs bucket, no real RSVP does (this PR)

Recommendation 4 of the workspace's `reports/2026-11-03-forms-spam-review/report.md`. Between 10-07 and 10-25 seven RSVPs reached Sonder with a one-word random name, a gmail address with 3 to 8 dots in its local part, and 13 to 161 guests. Every one scored 0 and was emailed. The operator's rule: score an RSVP a bot only when all three hold, because each alone describes some real guest.

The verdict is made in `classifySpam` (`src/forms/spam-classifier.ts`), which `form-ingest` calls for every form type, so the signal lives there, gated on `formType === "rsvp"` and scored at `SPAM_THRESHOLD` so it survives the separate card that is lowering the threshold to 50. No other branch touched the file when this one started (checked 20:35 UTC: four fresh branches, none under `src/forms/`).

**"Random name" was the only condition that needed a definition.** Several real guests type just a first name (brianne, carlo, Moncho, Kelly), so "single token" alone is not it. The rule is: one all-letter token with at least one consonant pair outside an allow-list of pairs English and common non-English names use (`y` a vowel), or a token ending in `q`. Across the 190 stored RSVPs it fires on the seven bots and on no real name. Against a hand list of about 160 real names of many origins it fires on about 60 (Farooq, Niamh, Krzysztof, Tadhg, Rhys…), so it is weak alone, exactly as the operator said, and a real guest is blocked only if they also use a 3-dot gmail address and bring more than 10 guests. Two bot names hang on one feature each: `pm` (kept off the allow-list) and a trailing `q`.

**Tried and dropped:** a "q not followed by u" rule. Mutant M12 survived it, because a q followed by a consonant is already an odd pair; the rule's only effect was flagging Aqil and Qasim. Vowel ratio and the existing gibberish-name detector were checked first and each missed two or more of the seven (the gibberish 7-run rule catches only one).
