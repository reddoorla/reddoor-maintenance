**Four review rounds; the first three were dirty, each with a reproduced major.** What each corrected is the useful part:

- **R1:** "Dependabot reported nothing" was the wrong trigger. One live Actions low switched the cross-check off, and a lockfile critical stayed hidden. It also found that an UNMEASURED protection sweep filed a "coverage gap" issue with no GAP line, which the close step can never close. Before this change that input filed nothing, so the fix had made something worse. It now reds the run instead, and the nightly-failure issue carries it.
- **R2:** an alert on `functions/package-lock.json` or any `package.json` is not proof that the root lockfile was read. Only a live alert on a root lockfile is. R2 also found that a night when `pnpm audit` cannot run wrote Dependabot's 0 over a lockfile known to be vulnerable, which reset the auto-fix counter. That night now skips, as the hidden-lockfile path does (#1561).
- **R3:** neither audit reads `yarn.lock`, so a yarn-only repo would have skipped every night. Only lockfiles the audit can read now decide whether there is anything to check.
- **R4:** clean, one comment nit.

**Why not cross-check every site.** 29-navy's real lockfile (all scopes) shows 0C/2H/5M/1L, where Dependabot said 0C/2H/3M/0L. The gap could be alerts an operator dismissed: this session's App gets 403 on the Dependabot alerts API, so it could not tell. Where a live alert sits on the root lockfile, Dependabot stays the source alone, as before. 29-navy's row stays as it was if its alerts are filed against `pnpm-lock.yaml`, which could not be checked here. #1659 is the dismissal guard for the cross-check path.
