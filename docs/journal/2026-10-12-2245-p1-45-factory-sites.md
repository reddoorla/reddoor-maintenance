This continues 2026-10-12 — The staging flow and kit 3 reach `staging` on vida and mantis. That entry stopped at "0.107.0 is not on npm". The operator published it, and la-homelessness-youth, gallerysonder and alamo-anatomy each went through the runbook in turn. Each repo got:

**The three sites were not the same port, and the differences were where the work was.**

- **la-homelessness-youth** has no vitest. Its kit-config gate is a `node:test` port of the starter's, run as `node --test 'scripts/**/*.test.mjs'`. A directory argument is run as a module, so the glob is needed.
- **gallerysonder** had five `$app/stores` users. Kit 3 throws `app_stores_removed` on that module, so every page would have thrown. Its first CI run failed on a kit 2 path in the slice-simulator spec, because kit 3 writes `.svelte-kit/generated/build/client-optimized/app.js`.
- **alamo-anatomy** prerendered its origin through kit 2's `prerender.origin`. Kit 3 dropped that option, and its replacement, `paths.origin`, is also the only origin the CSRF check accepts a POST from. So it got vida's `productionOrigin`/`define`/`siteOrigin` pieces, plus a `siteHref`, because its canonical and og:url read `page.url.href`. Seven places would have carried `http://sveltekit-prerender`. Built with `URL` set, none does. Built without it, 7 files do, which is the control that proves the grep can see the placeholder.

**Two instruments lied to me on alamo, and their own guards caught both.**

- Three mutation runs never applied, because a `\$` escape reached Python literally. The harness compares the file before and after, and it printed "did not apply" instead of a pass.
- The first source guard added after review broke its whole test file under jsdom, where `import.meta.url` is not a `file:` URL. The two mutations it was meant to catch "passed" at 22 tests. The total dropping from 24 to 22 is what gave it away. The harness now prints the failed-suite line too.

A third run looked like a finding and wasn't. The layout mutation's assert failed, because prettier had rewritten `href={href}` to `{href}`. The `&&` chain then skipped the rebuild, and the "5 files carry the placeholder" it printed came from the previous control build, made without `URL`. Rerun with a fresh build, the number is still 5, but only the rerun counts.

**I broke a running review, briefly.** To smoke-test production on kit 2, I symlinked the kit 3 worktree's `node_modules` into a worktree on the old `staging`. `pnpm exec` noticed the lockfile and relinked the shared store to kit 2.70.3 and svelte 5.57.0, under the review agent that was building in the other worktree. I saw pnpm's "Lockfile is up to date" line, checked the kit version, restored it with `pnpm install --frozen-lockfile` (22:32:01Z) and told the reviewer. It discarded the two reads it had made in that window and redid them. **Never symlink `node_modules` between worktrees whose lockfiles differ and then run `pnpm exec` there.** Reading `node_modules/.bin/<tool>` directly does not relink; `pnpm exec` does.
