**The parser is where five review rounds went.** The real file's rows are messy:
- P1-55's row is a single cell, and P1-83's has five.
- P1-82's item cell holds a status prepended over an older one, which leaves a `**` unpaired, so pairing `**…**` spans gave no title at all. Status prefixes are now peeled off one at a time instead.

Statuses then took four rounds of whack-a-mole. Each round's detection rule let through a new spelling that showed as the title:
- round 1: lower case, and no space before the date;
- round 2: a dash or a parenthesis before the date;
- round 3: four spaces, which my round-2 three-character window had reopened;
- round 4: `Status [M]:`, `Status Nov 12:`, code spans, links, `<s>`, and a zero-width space.

Round 4's fix inverted the rule: only an exact `Status YYYY-MM-DD` counts as a status, and any title whose visible text begins with the word "Status" fails loudly, naming the row. That rejects a real title like "Status page for clients" too, and was accepted as the safe way to be wrong.

**A belief corrected on contact.** The test cases I "added" in rounds 2 and 3 never reached the file. My Python insert anchored on a line Prettier had already reflowed, `str.replace` matched nothing, and the suite stayed green at the same count (31). Mutants 8 to 10 surviving is what showed it. The lesson for any scripted edit: assert the anchor matched (`assert s.count(anchor) == 1`), and check the test count moves.
