## 2026-10-19 — Bake-off row 3: review recall on real seeded defects; Opus `medium` within tolerance on a corrected key (P1-59, reddoorla/reddoor-workspace#1)

Row 3 of workspace#1 asks whether a cheaper model can do spec and code-quality review. Its gold is
objective: real defects, each with a known location, in the diff a reviewer would have seen. The task is
`scripts/model-bakeoff/tasks/seeded-review.mjs`, with its key, builder and frozen cases under
`tasks/seeded-review/`.

**The brief's source ran dry.** It asked for 6 to 10 fixed bugs from `docs/journal/`. Two Sonnet readers
swept all 90 entries and found two that qualify: `branchTip`'s 422 (#1368) and the approved row with no
refresh button (#1274). Everything else either landed in another repo, was fixed inside its own PR before
merge, or is a feature. So the key draws the other seven from `fix` commits on `main` whose message names
the defect, such as `c89b319e` (git clone argv injection) and `829a9974` (the Prismic uid lookup that can
PUT onto the wrong document). Each case is the commit that added the defect lines, cut to one file, with
`index` lines stripped so no blob id leads back to history. Three clean controls are commits whose files
nothing has touched since.

**What the instrument got wrong, in order.**

- Overlap alone was the first match rule. On the first score, every one of the ten runs that flagged r09
  line 118 had described a different defect: a rounding mismatch against `foundOnPage1`, not the seeded
  "#0". sonnet-high-1's trailing-slash finding got credit for path traversal the same way. Since then, a
  finding in the right case and file within 10 lines of a seeded range is a candidate, and the Opus
  referee rules on each one. The change came before the referee ran, and it can only lower a score.
- Two keyed defects were not in their cases. Round 1's validity lens found that r03, at `d1218ac6`,
  hard-codes `gaUsersCurrent: 0` and runs no GA query. So the boundary-day double count (d2, marked
  critical) did not exist until a later commit wired GA in. d9 was a feature gap: r11's own docstring
  sends a refresh through the pending list. Every run missed both, the gold included. Because the
  critical-miss rule is absolute, d2 alone put every arm "outside", the comparator included. Both stay in
  `key.json` as `excluded`, with the reason, and the results file reports both readings.
- The scorer's own review found a refuted defect still counting as a critical miss for every arm, a
  control finding listed twice counting as two false positives, and a finding with an unknown case id
  vanishing without a trace. All are fixed, and each has a mutation that turns a test red (nine in
  total).

**Result [M].** Two runs per arm, eleven agents, one referee round of 46 items. On the seven scored
defects (three critical), pooled out of 14: Opus `medium` 8 with no critical missed; Opus `xhigh`, the
comparator, 7 with one missed; Sonnet `medium` 5 (one missed); Sonnet `high` 5 (two missed); Opus `low` 2
(five missed). The Opus `high` gold found 3 of 7. No run flagged anything on the three controls, so the
false-positive slack was never exercised. Every transcript ran on the model and effort it asked for.
Cost per run: Opus `low` about $0.51, Sonnet about $0.29 to $0.64, Opus `medium` $0.85 to $0.96, Opus
`xhigh` $1.51 to $1.60. The whole run, referee included, cost $9.93, and the ledger agrees.

**Honest accounting.** Opus `medium` lands within tolerance on a key corrected after the run, with
seven defects and two runs. Every run missed d1, d4 and d8 (d4 and d8 only ever drew a different defect on
the same lines), so four defects, d3, d5, d6 and d7, carry the whole comparison, and the one difference
between Opus `medium` and `xhigh` is opus-xhigh-2's d6 miss. The comparator fails its own critical-miss
rule, and Sonnet `medium` clears the recall bar and is outside on one d7 miss: at two runs the absolute rule
barely separates arms. Run-to-run spread is as large as the gaps between arms: sonnet-high scored 1 and 4.
Arms worked in the repository checkout, where `git log -S` on a line from the input names the fix. Nothing
sandboxed that. The transcript audit, which found no git command and no read outside the input in any
arm, is the evidence that it was not used. No routing changed. A second, fresh case set should confirm
the result before Opus `medium` replaces `xhigh` for review.
