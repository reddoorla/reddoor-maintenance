**The status rule as it stands.** Every whole word "status", in any case, outside the title must open an exact `Status YYYY-MM-DD` with a valid date. The text must be plain or bold (not code, emphasis, strike, a link or straight after an HTML tag) and must stand at the start or after a space. Any other use, prose such as "check the status of" included, fails the whole section loudly and names the row and column, so the PM pass rewords it. A title that begins with the word Status also fails. A status's line runs to the next status, the title or the cell's end. The newest by date wins; on a tie, the first met.

**The rewrite (round 8, the operator's answer (a)).** Each cell is now parsed by `mdast-util-from-markdown` with GFM strikethrough and every block construct off. GitHub reads a table cell as inline only, and round 9 found that a cell starting `- ` had been read as an empty list. The libraries are devDependencies. Only the cockpit bundles the parser, and nothing in the package's tsup entries imports it. Our own rules run over a flattened text in which each character carries a kind (`plain`, `code`, `marked`, `html`, `title`). Row splitting stays hand-written, because GitHub splits a row on a `|` inside a code span and the real file has one. `splitRow` rejoins pieces that a code span spans. The rewrite kept all 72 tests and 22 mutations as its gate. On the real file, all ten P1 rows gave the same title, tier and status as the old parser.
