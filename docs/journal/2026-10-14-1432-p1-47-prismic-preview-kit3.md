## 2026-10-14 — Ending a Prismic preview works on SvelteKit 3 (P1-47, #1369, reddoor-starter#188)

`@prismicio/svelte`'s `PrismicPreview` ends a preview with `goto(url, { invalidateAll: true, noScroll: true })`. Kit 3 replaced `noScroll` and `keepFocus` with `reset: false`. In kit 3.0.1, `goto` checks with `'noScroll' in opts` inside a `DEV` block, so the dev server throws on the key whatever its value. A production build compiles the check out, ignores the key, and resets scroll. The backlog item called both failures inferred from a reading of the source. This session measured them on the starter in Chromium: `/privacy` with the `io.prismic.preview` cookie, scrolled to 600 px, then `prismicPreviewEnd`. Dev gave an uncaught `goto_options_removed`. The `vite preview` of the build went from 600 to 0. With the fix, both stay at 600, and `history.length` goes from 2 to 3. That last number is the positive control: without it, "scroll unchanged" would also be what a listener that never fired looks like.

The fix in the starter is a local copy of the component, not a pnpm `patchedDependencies` entry. 2.2.2 and 2.2.3 ship byte-different files (2.2.3 dropped its semicolons), so a patch would have to be keyed to one exact version. At five sites on whatever versions their lockfiles hold, the next Renovate bump would fail the install. The copy passes `{ refreshAll: true, reset: false }` and calls `refreshAll()` on update. That is exactly what prismicio/prismic-svelte#64 ("feat!: require SvelteKit 3", pushed 10-14 02:38Z, published only as `2.2.3-pr.64.*` builds) does. The brief asked for an upstream issue, but none was filed because that PR is the fix. Swapping back to upstream once it releases changes no behaviour.

The starter test renders the real root layout rather than the component alone, so it also catches a layout that goes back to importing upstream. It was red against upstream, and red for each of the two mutations (`noScroll: true` restored, `reset: false` dropped). Here the kit peer is widened to `^2.0.0 || ^3.0.0` with a patch changeset. `tests/build/kit-peer-range.test.ts` reads the caret majors and goes red when the range is narrowed back to `^2.0.0`.

Nothing was pushed to the five client repos. The port note is in BACKLOG's Done entry for P1-47, and they stay broken in production until the operator rolls it out through each `staging`.
