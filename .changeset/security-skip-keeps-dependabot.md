The security audit no longer drops Dependabot's live alerts when a site's lockfile is hidden from GitHub's dependency graph (pnpm 12) and `pnpm audit` cannot run (#1561). It reports Dependabot's result with a note that the lockfile audit could not run, and writes it as a partial run. The merged audit now records on each advisory whether the lockfile audit reported it (`lockfile`), and the row persists each advisory's GHSA. On a partial night the stored advisories the lockfile audit found stand in for it, and tonight's Dependabot alerts are merged with them by the same `mergeAudits` a full night uses, so severity, relationship, scope and per-manifest folding read the same on every night; an alert Dependabot alone found and has since closed drops out. A partial run leaves `Last security audit at` as stored, so the Security Updates auto-tick reads the row as stale or unaudited rather than freshly clean. With no live Dependabot alert the audit still skips and writes nothing.
