`ensure-site` creates sites in Turso (#539 Phase 6 step 3, #646). A new site gets a `site_<ULID>` id, and its `sites`, `site_health` and `site_schedule` rows are inserted in one transaction. No Airtable record is created. Re-running for the same slug finds the site again and never mints a second id. A slug collision is refused. `--name` changes `sites.name` only. It never changes `sites.slug`, and a name that would give a different slug is still refused. Existing `rec…` ids stay as they are. For those sites, fill-blanks and renames are still copied to Airtable in one update, and the #645 heal still adopts an Airtable-only site under its `rec` id when Airtable credentials are set. Every Airtable site writer (`update*` in `websites.ts`, and `uploadAttachment`) now skips an id that does not start with `rec` and logs `AIRTABLE_SHADOW skipped=non-rec-id writer=<name> id=<id>`. The writers that return a FieldSet still return it. `createDraft` refuses a non-`rec` site id by name, because report ids are still a pending decision. Until #646 step 4 lands, batch jobs that list sites from Airtable will not see a site created this way. No migration.
