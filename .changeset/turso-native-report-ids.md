Reports are created in Turso with a `report_<ULID>` id (#539 Phase 6 step 4, #646, operator decision 2026-09-17). `createReportDraft` mints the id and Turso owns the row; the drafting path, the `launch` recipe and the `announce` recipe all go through it, and none of them creates an Airtable Reports row any more — the shadow skips a report id Airtable cannot hold, logging `AIRTABLE_SHADOW skipped=non-rec-id writer=createReportDraft id=<id>`. Existing `rec…` report ids are never rewritten and their Airtable rows still receive shadow writes; both shapes coexist. Every by-id Airtable Reports writer (`setDraftReady`, `updateReportScores`, `updateReportCommentary`, `stampSent`, `setDeliveryStatus`, `approveReportRow`, `overrideReportRow`) now skips a non-`rec` id with that same line. `/api/reports/:id/preview`, `/rerender` and `/commentary` accept both id shapes (`isReportId`); the `rec` half of that check is the routes' previous regex, unchanged. The reads the report paths still made against Airtable moved to Turso: the nightly `report --due` batch takes its roster and its report list as injected reads (`listSites` / `listAllReports` over one connection), `report <slug>` resolves the site from the fleet roster, the single-queue rule and the period derivation read the site's reports from Turso, and `launch` / `announce` enumerate the fleet from the roster and dedupe a re-run with `findReportForPeriod`. A `site_<ULID>` site can now be drafted, queued, approved and sent with no Airtable record anywhere. No migration.
