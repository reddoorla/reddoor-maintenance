New standalone recipe: `reddoor-maint match-harness [site] --ref <url>` installs the matching harness — the `/dev/match/[uid]` route, the `matching/` gate scripts and their one read layer, the site records, and the `.gitignore` / `.prettierignore` / `CLAUDE.md` blocks — in a single commit on its own branch.

It is not part of `init`. A harness needs a live reference to gate against, and `--ref` is required for exactly that reason: a harness with no reference can only ever report an absence of errors, so the recipe refuses rather than installing something that would go green on nothing. `--cand` and `--matrix` override the SvelteKit dev server and the fleet's 1440 / 834 / 390 breakpoints.

**Everything specific to a site is data.** `matching/harness.json` holds the page table, the two hosts, the matrix, the threshold and the reference marks; `matching/harness.mjs` is the only thing that reads it and the only place the skill path is written down. That split is the whole point of the recipe. On the site it was cut from, the page table, the two hosts, the matrix and the skill path had been hand-copied across the harness one script at a time — a table that goes stale the moment an anchor list changes, and a wrong denominator makes the score a lie in the flattering direction. After the consolidation exactly one of that site's scripts still carries a hand-typed copy of the full nine-row table (measured on `main`: `matching/probe-chrome-count.mjs`), and everything the recipe itself installs reads the table from `harness.json`. Edit `harness.json`; never `harness.mjs`.

**Records are never rewritten.** Files a site authors — `harness.json`, `LEDGER.md`, `floors.mjs`, `census-deviations.mjs`, `spec-sections/`, `site-pages.js` — are install-if-absent and are not touched again. Recipe-owned scripts are byte-compared: one still matching a previously shipped render is safe-replaced; one that has been hand-edited is FLAGGED in the notes and left alone, so an operator's change is never silently reverted and never silently kept as though it were ours. CRLF and trailing whitespace are the only differences that still count as ours.

**The recipe hands the site's prettier only files the site OWNS, decided by the file table's `owner` column and never by path.** An earlier draft of this branch filtered on the `src/` prefix, which is not the same rule: three recipe-owned files live under `src/` — `src/routes/dev/match/[uid]/+page.server.ts`, its `+page.svelte`, and `src/lib/site-pages.test.ts`. Measured 2026-09-09 by installing into a fixture and reading the bytes back: on `beachfront-dentistry` and `1836dig`, which ship prettier's bare defaults (printWidth 80), the install rewrote two of the three; on `erp-industrial`, `gallerysonder` and `welcome-to-the-flower-court` (`useTabs`, `singleQuote`, `trailingComma: "none"`) it rewrote all three. `normalize()` forgives only CRLF and trailing whitespace, so the second run reported each as `differs from the shipped template and was left alone (hand-edited?)` — nothing but the recipe's own formatting step had touched them, and the recipe could never upgrade its own route or its own test on those sites again. The remaining 14 of the 19 clones carrying a prettier config set printWidth 100, which happens to match the templates and hid the whole thing.

Two independent forces had to be closed, because either one alone re-breaks it. The recipe no longer hands prettier a file it owns — an allow-list keyed on `owner === "site"`, so a file added to the table is not formatted until someone says the site owns it. And those same three `src/` paths join `matching/*.mjs`, `matching/*.sh` and `matching/harness.json` in the `.prettierignore` block, so the site's own `prettier --write .` cannot do the identical damage. **The route's bracketed segment is written `src/routes/dev/match/\[uid\]/…`, escaped:** `.prettierignore` is gitignore glob syntax, in which an unescaped `[uid]` is a CHARACTER CLASS matching one of `u`, `i`, `d`, and ignores nothing at all — measured both ways with `prettier.getFileInfo`.

Site records under `matching/` (`LEDGER.md`, `spec-sections/`) are now formatted on install, which they were not under the `src/` prefix rule; `floors.mjs`, `census-deviations.mjs` and `harness.json` are handed over too and prettier skips them, being in the ignore block. The Markdown stubs are still authored prettier-clean and the test that proves it stays: a site with no usable prettier takes the flagged degraded path and gets them unformatted, and they stay inside that site's own `prettier --check .` either way.

Also worth stating, because the `.prettierignore` block looks over-specific: under `matching/` it ignores `matching/*.mjs`, `matching/*.sh` and `matching/harness.json` rather than `matching/`. **eslint does not lint Markdown**, so for `SPEC.md`, `LEDGER.md` and `spec-sections/` prettier is the only style check there is, and a blanket entry would leave the records with none. The comment shipped in that block previously justified the narrowing differently — "eslint already ignores this whole directory (eslint.config.js:52)" — which is true only of the one site the recipe was cut from. The eslint config this package writes (`src/configs/eslint.ts`) contains no `matching/` entry at all, so on every site the recipe installs into, that reason was false while the conclusion stayed right. Corrected here; whether the recipe should also install an eslint ignore is open in reddoorla/reddoor-maintenance#730.

Three of the new tests shell out into the installed site rather than comparing bytes, because a recipe that copied a working harness and a recipe that copied a broken one are byte-identical from the outside. `matching/next.mjs` must refuse an empty corpus with "no parseable gate run" and exit 2 rather than print `SCORE 0/0`; `matching/gate.sh` must refuse the seeded reference because `refMark` ships empty — the fail-closed default, since a fresh install cannot produce a score until someone names a string only the reference serves; and once a verified reference answers, the same command must get past `--check-ref` to the Phase 1 refusal, `REFUSED: no '## home' section in matching/SPEC.md`. The last two both exit 2, which is why each asserts on its own message and on the absence of the other's.

**An install git did not take is a failure, not an "applied".** The recipe writes 17 files plus three appended blocks and commits with `git add -A`, which honours the site's .gitignore and exits 0 either way — and git cannot re-include a file whose parent directory is excluded. A site that already ignored `matching/` therefore got 13 of the 20 installed paths on disk, none of them in the commit, and a result of "applied": a `/dev/match` route, a `site-pages.test.ts` and 83 lines of CLAUDE.md rules naming `matching/gate.sh`, `matching/next.mjs` and `matching/harness.json` that existed on the operator's machine and nowhere else. The recipe now asks git what actually landed — every installed path must be FOUND in `git ls-tree -r -z --name-only HEAD` — and refuses otherwise, naming each absent path and the `<file>:<line>:<pattern>` that excluded it. The check runs over the whole manifest, not this run's writes: where the files are already byte-correct on disk the run writes none of them, so a delta check would pass over a commit containing none of them. Before returning, everything the run wrote to a refused path is put back as it was, so a refusal leaves the checkout byte-identical to how it found it. A pre-write ignore check was tried and rejected: a site ignoring `*.sh` or `*.mjs` installs correctly, because the block's own `!matching/*.sh` / `!matching/*.mjs` come after the site's rule and the parent directory is not excluded — checking before the block exists would refuse two working configurations.

`matching/census.sh` will not report a count it did not measure. It printed "Phase 3 CLEAN" and exited 0 with `style-census.mjs` absent — every run died on module resolution, `census-count.mjs` read each crash log as "0 0 0" because it counts `  y=` rows and a stack trace has none, and no rows was reported as no mismatches. The exit status could not have caught it: style-census exits 1 both when it finds mismatches and when it dies before it looks. Three guards now demand an artefact instead. The tool must be installed and must answer style-census's own `--ref`/`--cand`/`--vw` usage banner — the substitute for the `page-diff --version` schema check `gate.sh` runs, since style-census has no `--version`, and it is not a free probe because the banner is printed only after `playwright` has been imported. Each run must leave the header and counts line style-census writes together after walking both pages, with non-zero run counts on both sides, so a crashed run and a pair of blank pages are both refused rather than counted as zero. And a census over no pages — an empty table, or a page name that matches nothing, the refusal `strikes.mjs` already had — is not CLEAN either. Everything refused exits 2 and says which guard refused. `census-count.mjs` no longer answers "0 0 0" for a log it cannot open.

**And the count reported is the count the census MEASURED.** The first pass at the guards above did not close the class it named: they matched the counts line with `grep -qE` — an answer to _is it there_ — and threw its numbers away, then reported whatever `census-count.mjs`'s row parse had found, with nothing comparing the two. A COMPLETE census whose counts line said `mismatches: 3`, whose `y=` rows carried one leading space instead of two, was reported as `0` and printed "Phase 3 CLEAN", exit 0. The two readers version in different repositories — the printer is `style-census.mjs` in the matching-a-page skill, the parser is `census-count.mjs`, copied byte-for-byte into every site the recipe installs — so drift needs nobody to touch either repo, and one space is enough (`census-count.mjs:39` matches `/^ {2}y=/`). They are now compared: exactly for mismatches, because style-census prints at most 100 rows and states the remainder on its own line, so parsed + remainder == reported; as a floor for ambiguous rows, because the cap is the same but the remainder is not stated.

Fourteen census cases shell into the installed site. Two of them are the ones that matter, because they prove the guards can still say yes: a census that ran and found nothing still reports CLEAN and exits 0, one that found a mismatch still exits 1, and a census of 137 mismatches whose print truncates at 100 is COUNTED rather than called drift — dropping the remainder term reddens exactly that case and nothing else.

**The recipe never shells out into a client checkout to find a prettier.** It called `formatWithPrettier` with neither `bin` nor `timeoutMs`, which builds `pnpm exec prettier --write …` (`src/recipes/_prettier.ts:90-94`) and, because `src/audits/util/spawn.ts` sets `detached` and installs its kill timer only when `timeoutMs` is present (lines 91 and 136), ran it with no timeout and no process group to kill. On `--fleet` that is the normal path, not an edge case: `prepareFleetSites` calls `cloneIfNeeded`, and `src/cli/fleet/clone-if-needed.ts` contains no `pnpm` or `install` token at all, so every site arrives without `node_modules`. Recorded from the pre-fix code in a fixture with no `node_modules`, the recipe's one spawn was `cmd: "pnpm"`, `args: ["exec", "prettier", "--write", …8 paths]`, `opts: { cwd }` — an unrequested, unbounded install in a live client repo, which in a repo whose install leaves no prettier of its own then falls through to the CALLING repo's binary and exits 0, reporting success for a format the target never did. The recipe now resolves the site's own prettier POSITIVELY with `resolveTargetPrettier(cwd)` and runs it by absolute path under a 60s timeout — the same shape `prismic-ci` uses (`src/recipes/prismic-ci/index.ts:285-294`) — and when the site has none it SKIPS the format entirely and flags it, rather than installing on the operator's behalf or formatting with someone else's binary. The honest consequence: a fleet run now returns the prettier flag note for every cloned site, because a fresh clone has no prettier to run; the note stops discriminating in fleet mode and CI's format check is what to read instead.

**The guards are executed, not inspected.** A refusal-only suite cannot tell a working guard from one that refuses everything, and until now the two guards with the largest blast radius had no case at all: deleting `if (!dev) error(404, …)` from the shipped route template left the whole suite green, and so did removing five of `checkRef`'s eight refusal arms at once. Both are now run. The `/dev/match/[uid]` route's `load` is EXECUTED under both values of `dev` — production must 404 with the guard's own `"Not found"` while a `home` assembly is sitting there for it to return, and dev must return that assembly with the route's own image resolver applied — by supplying the route's three bare specifiers as stub packages under a tmp site's own `node_modules` and letting Node strip the file's two type annotations, so what runs is the byte-for-byte template the recipe wrote. `checkRef` is exercised through the same `node matching/harness.mjs --check-ref` CLI that `gate.sh` calls, once per refusal arm (a host in `selfHosts`, a host equal to the candidate's, an unreachable host, a non-200 that carries `refMark` anyway, a 200 that carries a `Location` header, a 200 without `refMark`, a body carrying `candMark`) and once for the grant, each case arranging every OTHER arm to pass so a green is that arm and nothing else. `next.mjs` must SCORE a real corpus — `SCORE 2/3`, `NEXT: home`, `@1440 top pixels 50.0%` — and then be silenced by `matching/PAUSED` over that same corpus, which is the only way to tell the pause switch from a script that had nothing to say. `gate.sh` must reach `ALL DONE (smoke)` once the reference verifies and `SPEC.md` carries the page's section, so the two pre-existing refusals are pinned from both directions. And the installed file list is now compared with a HAND-WRITTEN 17-row manifest and read back through `git ls-files`: every other case in the file loops the generated `MATCH_HARNESS_FILES`, so deleting a row deletes its own check.

**And the CLI command is reached.** `matchHarness` had never once been invoked through `reddoor-maint match-harness`: the only CLI test that named it mocked `resolveSites` to an empty inventory, so the command ran its argument handling over zero sites and exited 0. Six cases now exec the built `dist/cli/bin.js` against a fixture site — `--ref` installs and commits, `--cand`/`--matrix` reach `harness.json`, a missing `--ref` exits 1 having written nothing, and `--matrix 0` is refused. That last one is why the option is normalised with `String()` and branched on presence rather than truthiness: cac type-coerces a numeric option value, so `--matrix 0` arrives as the NUMBER `0`, and a truthiness test silently substitutes the default `[1440, 834, 390]` and exits 0 — telling an operator who asked for one thing that they got it.
