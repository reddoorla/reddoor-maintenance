`sync-configs --fleet turso --dry` reports a roster row whose Status is outside the vocabulary (a retired name like `maintenance`) as `SKIPPED … status "maintenance" is not in the vocabulary`, where before the row was silently dropped: such rows now count toward `total` and the weekly drift run's skipped-share gate (#1607). The weekly run also goes red when found drift reached no issue: `gh issue create` failed, or both rewriting and commenting on the open issue failed. `renovateActionGaps` reports a renovate.yml in which Renovate cannot run because of a literal constant-false `if:` (`false` or `0` bare, `${{ false }}`, `${{ 0 }}`, `${{ null }}`, or a YAML string `"false"`, `"0"`, `"null"` or `"''"`): on every job that runs `renovatebot/github-action`, on every such step, or on every `create-github-app-token` step of its job. Such a file used to read `CLEAN`. An empty or null `if:` runs the job (GitHub reads it as `success()`), so it is no gap; nor is a site's own job or step, a disabled second copy beside a working one, a disabled checkout, or a key named `if` inside `env:`/`with:`. Quoted literals inside `${{ }}` (`${{ 'false' }}`), padded quoting, block scalars holding an expression, and expressions such as `false && x` are not read: a miss, never a gap. The new `rowsWithUnrecognizedStatus` and the `onUnrecognizedStatus` option of `fromTursoDb`/`resolveSites` expose the dropped rows to any sweep.
