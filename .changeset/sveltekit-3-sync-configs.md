SvelteKit 3 support in the config factory and `sync-configs` (P1-45). `createKitConfig` in `configs/svelte` returns kit 3's options top-level for the `sveltekit(...)` plugin, with the canonical warning filter, aliases (plus `$lib`, which kit 3 stopped providing), opt-in `csp`, `prismicRepository` and `placeholder`. On a site whose `package.json` declares `@sveltejs/kit` 3 or later, `sync-configs` heals a `sveltekit.config.js` off the canonical adapter and an `eslint.config.js` to import it, never writes a `svelte.config.js`, writes neither file when the config is inline in `vite.config.ts` or the kit spec is unreadable (`catalog:`, `workspace:`), and reports what a sync cannot fix (a leftover `svelte.config.js`, an `eslint.config.js` still importing it, an unreadable kit spec) in its notes and, when `svelte` is targeted, as a `DRIFT … (move by hand, sync-configs will not)` line in `--dry`. `analytics-tag` refuses a kit 3 site, whose CSP it cannot yet edit, instead of installing a tag the CSP blocks.
